# SPEC-023：完整角色、名冊與續玩保存

狀態：**READY**（2026-09-08）。使用者明確要求完成 v1 匯入、建角回填、住宿交易與世界時間。

## 正式接線審查

- v2 根物件沿用來源、設定、時間戳與位置；`characters`、`party`、`speaker`
  採下節保存核心。七項屬性等完整內容以角色名冊為唯一保存來源。
- 世界 `clock` 保存 Ticks、Part、Day、Month、Year、Weather，依 RE-077 與
  `world/clock.go` 的五時段、無閏年日曆與 4200 倒數檢查範圍；讀回後同步日期、
  天候及時段畫面。住宿保存不發生於露營確認或戰鬥中，不保存這些暫態畫面。
- v1 匯入只補舊檔未保存的欄位：以既有固定來源名冊作基底，再覆上 v1 已存值。
  原始 v1 保留，寫入使用不同的 v2 路徑；顯示無法還原未保存變更的限制。
  不認得的角色不能猜造能力，匯入失敗並說明。
- 住宿逐人交易先更新該角色的名冊與付款後狀態，忠實模式再形成離隊後隊伍，
  整份原子寫入成功才保留更新；失敗退回本人的金冠、所在地、名冊及隊伍。
  已完成的前一人交易不回滾；便利模式保留隊伍。
- 建角沿用 SPEC-005 起始契約與 REGION 路由，接受肖像時才寫入空槽。
  資料來源未備齊時不得用既有角色屬性代填；保存失敗保留可重試的建角草稿。
  刪除需在同一保存交易中移除槽位，禁止刪除仍在隊伍中的角色。
- 槽位用於名冊定位，永久角色身分另存 ID；重用空槽時產生新 ID，符合 SPEC-005。

## 已審查的保存核心（READY，2026-09-08）

本節限定 remake 自有保存核心；正式接線契約見上節。
依據為下表列出的既有 RE／規格及 `town.Member`、`Sheet`、`Good` 的實際欄位，
不新增原版規則，也不表示原版存檔格式相容。

- 目前正式格式是 `kol-save-v3`：與 v2 相同，另在每名角色上加 `picture`／`shield`
  兩欄（書本 EDIT PICTURE／EDIT SHIELD 改過的 760 byte 圖，十六進位字串；`null` 表示
  沒改過，圖像用 `portrait` 那張模板、盾牌用新角色的預設盾牌，SPEC-036）。讀到 v2
  時補上兩欄 `null` 後當 v3 處理，寫出一律 v3。
- `kol-save-v3` 使用長度固定 16 的 `characters` 陣列；索引就是穩定槽位，
  `null` 表示空槽／已刪除。刪除不得壓縮槽位；新建角色才可重用空槽。
- `party` 保存有序槽位索引，上限六人，不可重複或引用空槽；`speaker` 保存
  隊伍內索引，空隊伍為 -1。角色資料只有名冊這一份，不另存容易分歧的隊伍副本。
- 角色保存完整資料頁、七屬性、四列武器熟練度、手持、十格穿戴、最多六格背包、
  信物、坐騎、法術、教派、六格任務旗標、五格進度與十七格 16-byte 物品資料。
  物品保存完整骰式、耐久、合身資訊及原始記錄；不存在的裝備明寫 `null`。
- 欄位省略與合法空值不同：v3 讀取必須拒絕缺欄、錯誤陣列長度及錯誤參照，
  不可把缺欄轉成零值後當成完整保存。不得載入原始名冊補回已存角色的空物品。
- 保存 DTO 不依賴城鎮／UI 狀態機；不保存函式、畫面資源或原版檔案。
- 正式保存用 v3；v2 讀取時遷移，v1 僅為相容匯入入口。完整續玩的完成聲明須另附正式路徑驗證，
  不能只根據保存核心單元測試。
日期：2026-09-08。本文件為目前程式與既有規格的缺口盤點，不是原版新增 RE 結論。

## 接線前確認的實作缺口

`cmd/kol/main.go` 的 `buildSave`／`savedParty` 與 `internal/save/save.go` 只保存
部分隊伍欄位。`town.Member`／`town.Sheet` 中實際存在而未完整往返的狀態包括：

| 垂直鏈 | 需要保存及還原的內容 | 既有依據 |
|---|---|---|
| 建角 → 名冊 → 選隊 → 招募 | 16 槽占用／刪除狀態、穩定角色身分、完整角色資料 | SPEC-005、roster／flow |
| 訓練 → 資料頁 → 戰鬥 | 七項屬性、武器熟練度與原始攻防值、冒險點數／位階 | RE-074／076、town.Sheet |
| 商店 → 物品頁 → 戰鬥 → 戰後 | 手持、十格穿戴、六格背包、物品 Condition／Record／Carried | RE-075／109／127、town.Member |
| 施法／入會 → 戰鬥 → 續玩 | 法術、教派、信物、Ward 等角色可變資料 | RE-100／121／128 |
| 任務 → 回報 → 續玩 | Quests、Progress、任務物品與獎勵後角色數值 | RE-101／107／109 |
| 世界探索 → 住宿 → 重載 | 座標、次格、世界時間及影響後續規則的狀態 | SPEC-006／007，待逐欄盤點 |

上表是保存範圍，不能直接序列化整個 UI／Session 物件：地圖、資產、函式、視窗與
暫態選單應由正式啟動流程重建。schema 欄名與身分配置依上節已審查契約。

## 必須保持的既有契約

- SPEC-006 的住宿保存時機、住宿設定及付款失敗回復契約。
- 原版 CHARDATA 與素材仍為唯讀；remake 寫自己的保存格式。
- 零金冠、零熟練度、空裝備、刪除槽位皆須保留其實際意義，不能回退預設名冊。
- 未知設定鍵往返保留。已保存的可變資料不得再被原版 typed data 靜默覆蓋。
- 保存錯誤不得破壞既有檔案；角色資料與名冊必須採一致的交易邊界。

## 已完成的決策與證據審查

1. 已決定：v2 支援匯入 v1，保留舊檔。匯入無法找回舊格式從未保存的遊玩變更，須明示限制。
2. 槽位不隨刪除移動，角色另有持久 ID；空槽重用產生新 ID。
3. 住宿每人各自提交完整名冊與成交後隊伍，寫入失敗只回滾目前這人。
4. 世界時間依 RE-077 的既有 Clock 契約保存；隨機遭遇由時段變更觸發，
   無額外的每日累計計數需要保存。系統時鐘與未受控 RND() 序列不列入對拍要求。

## 驗收要求

- 新建兩名角色 → 入隊 → 保存 → 離開 → 重啟，名冊與隊伍正確；刪除、滿槽也驗。
- 訓練、裝備交換、破損、任務回報後，逐欄往返一致。
- 住宿逐人／全隊、便利／忠實模式各自保持已核准規則；失敗不留下半份狀態。
- 正常 GUI 保存及 `-load` 重啟，不以直接注入隊伍的測試代替完整玩家驗收。
- 原版行為對拍與 remake 自有檔案往返分開陳述；涉及 RND() 依固定 seed 鐵則執行。
