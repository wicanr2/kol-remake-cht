# SPEC-019：戰鬥左上肖像與裝備模式

狀態：**CONFORMED**（2026-09-30：原版正常戰鬥同一刻的裝備列與受控破損之後的裝備列與 remake 一致，見 `docs/verification/battle-panels-20260930.md`）；2026-09-08 同日 DRAFT 經原版測試與下列證據審查升 READY。本規格補接原版已有資訊，與 SPEC-018 共用被檢視者。

## 已證實證據

輸入 `KOLTOWN-unpacked.EXE`，SHA-256
`01f6f9a95c4adf8e9da59fa83bae57aa282e5576767b41bfc2f23302aeb9d1d2`。
IDA Pro 9.4，以下位址均為 IDA linear；DGROUP 基底 `0x2DED0`。

- `0x1F0EA..0x1F155`：新隊員規劃開始時 `word_303FC=0`，預設肖像模式。
  取消子選單返回 `0x1F16A` 不經該重設點，保留目前模式。
- `sub_228B7:0x22D13..0x22D1A` 以 4 或 5 呼叫主圖示讀鍵。
  `sub_11722:0x118BE` 在這兩模式按空白時反轉顯示模式，仍須 Return 才確認圖示。
  `TestBattlePanelSpaceOriginal` 十二組模式／初值通過。
- `sub_24131:0x2473D..0x24754` 選目標時僅在正在檢視人物的情況接受空白切換；
  空格不切換。`TestBattleTargetPanelSpaceOriginal` 有人／空格通過。
- 隊員名稱位置為 (24,7)，肖像在 (56,37)，大小 40×38；來源為角色縮圖快取
  `DS:0x3254 + 760*角色索引`。`TestBattlePortraitPositionOriginal` 首末隊員通過。
  既有角色抽取器已把每格 760 bytes 逐像素比對 CHARPICS 的 80 張模板，保存 Portrait。
- 裝備模板為 KOLDATA 0x101：`~V18~H03W:@H:@T:@L:@S:@B:@`。
  名稱從 (40,24) 起，每列 6 像素；六個隊員位移為 0x30、0x100、0x110、0x120、0x160、0x190。
  敵方為五格 0x20..0x60；不顯示第六格 B。`TestBattleEquipmentRowsOriginal` 四個邊界角色通過。
- 怪物肖像讀 MONPICS 的成對原始 payload，正式 PNG 將一對合成一個怪物單位。
  位置為 `x=(3+(15-width/8)/2)*8,y=76-height`；尺寸表讀 DS 相對 0x1370。
  `sub_22EFC:0x22F35..0x22FB9` 與既有 EGA manifest 為依據。

## 正式接線

1. 新隊員開始規劃重設肖像模式；取消回主指令不重設。模式切換不選圖示、不改指令或 RNG。
2. 主指令列空白切換模式；目標格有人時也可切換，空格不動。
   保留其他已存在的操作入口，本規格不擴張未審查的子選單鍵位變更。
3. 角色肖像索引從 town.Member 接到 battle.Member，不讀原版存檔或解析專有圖片。
   CHARPICS 必須 40×38；MONPICS 尺寸須與既有已驗證資產一致，不以版本號猜尺寸。
4. 裝備名稱直接讀取現行完整物品。護甲破損後不得回退至初始名稱；
   丟棄、拾取、腰帶交換使用既有可變資料，盾牌名稱由對應穿戴格帶入。
5. 與 SPEC-018 共用人物可見度及選擇；法術清單仍在左上覆蓋，不把裝備畫在清單之上。
   裝備名稱使用既有原版小字型；原版物品名稱至多十二字，文字限制於資訊框內。
   人物姓名另用原版大字型及輸入大小寫，見RE-250的正常像素驗收。
6. 初次 READY 時 KOLDATA 0x102／0x103 彈藥標頭與數字尚待釐清。
   後續由 SPEC-022 的 READY 增補取代此限制；左下命令依 SPEC-021。
   完整正常原版對拍仍列 A10，不因局部接線宣稱資訊框全部完成。

## 驗收

原版模式切換與空格行為、首末隊員／敵人裝備位移、肖像位置；
remake 模式不影響指令／RNG，取消保留、新人物重設；護甲破損及物品交換後名稱同步。
正常 GUI 以空白切換兩種模式並回復。完整測試、建置及來源收據通過後仍保持 READY，
dosgolem 正常戰鬥同狀態與其餘資訊未完成前不宣稱 CONFORMED。

READY 審查：四項原版測試涵蓋二十組輸入／邊界，均通過；首次位址別名初始化錯誤
已修正且保留收據。角色縮圖來自既有逐像素匹配結果，怪物成對 payload 來自既有
PNG manifest。靜態圖片只作來源，裝備列必須讀取戰鬥中可變資料，不能使用開場快照。

## 2026-10-01 繁中第六列勘誤

實作前的子契約審查：**READY**（上述既有原版契約與顯示消費端逐項審查通過）。玩家可見第六列原譯「身體」，但既有本規格的六列位移
與 SPEC-010／RE-094 已確認 +0x190 是腰帶武器；重製 `EquipmentPanel` 也讀取
`BeltName`。因此依術語表「入鞘／切換」使用的腰帶名稱，改標「腰帶」。
不改原始 B: 鍵、來源記錄、座標、亂數、裝備規則或保存格式；原版語意已證實，
此為繁中譯文回填，不新增原版逆向結論。

審查依據：本規格的固定 EXE 雜湊與 IDA 線性定位仍有效；SPEC-010 的
0x30／0x190 全記錄交換及 RE-094、`internal/battle/equipment_panel.go` 的
`m.BeltName`、術語表已核准的「入鞘／切換」共同指向腰帶。
初始穿戴盾牌應讀 +0x160（`equipment[6]`），不是 `equipment[4]`；
驗證模型及護甲母體須按正式消費端位移取值。

驗收：最寬護甲實際母體預先選樣；從標題、六人招募及自然遭遇核對六人裝備欄。
英中狀態、切換前後復原、完整文字框與正式字模像素核對通過；
96 像素護甲必須在 95 像素反例中被拒絕。原版／其他畫面與平台驗收不擴張。
