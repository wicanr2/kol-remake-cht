## 原版行為契約

### 1. 戰場視窗（`已證實`）

視窗外框 `(151, 7)–(296, 152)`，內容區 (152, 8) 起 144×144，剛好九列九欄、
一格 16×16。第 (列, 欄) 格取的地形是

```
地形[夾限(鏡頭列 − 4 + 列) × 64 + 夾限(鏡頭欄 − 4 + 欄)]      夾限在 0…63
```

鏡頭是**目前輪到的那一名**的座標：X 是列、Y 是欄。地形磚圖是 `KOLPICS`
payload 8（帶任務時 12），一列 10 塊。

任務地點的地形取自 `TOWN0` payload 0x3D + i（RLE），**不重新生成**，
但進場時照樣灑一次樹叢：擲 100 次 1…6 加總得到次數，每次挑一格
（`rand(4096) − 1`），原本是 0x09 或 0x0D 才換成 0x0A。灑點是亂數，
remake 的亂數來源與原版不同，因此這幾格不列入逐像素對拍。

### 2. 視線（`已證實`）

進場先把 81 格的可見度設成「還沒看到」，再對每一格從行動者拉一條線
（主軸每步走一格、誤差項滿了副軸才走）。線上每一格若還沒定值就判斷：

- 磚塊在位元圖 `ff 80 01 ff f1 ff 17 f9 76 7f` 裡的位元沒設 → 看得到，繼續；
- 位元有設 → 擋住：那一格看得到，線到此為止；
- 例外：磚塊落在 0x23…0x2D、行動者站在 0x24 或 0x25 上、而且是線的第一步 → 看得到，繼續。

還是「還沒看到」的格子畫磚塊 0x4A（全黑）。中心格不會被線標記，
但原版另外畫，因此永遠看得到。

### 3. 參戰者與游標（`已證實`）

站在格子上的參戰者疊在地形上：隊伍第 n 名畫磚塊 n（圖上有 1…6 的號碼），
敵人畫磚塊 6，倒下的敵人 7、倒下的隊員 8，地上的東西 38。疊法是
把精靈四個平面 OR 成剪影，每一列當成一個 16-bit word 往左右各推一格加寬
（`s | s<<1 | s>>1`，低 byte 是左半邊），加寬到的地方畫精靈、其餘留地形——
精靈四周因此帶一圈黑邊。目前輪到的那一格外面再畫 (216, 72)–(229, 87) 的白框。

### 4. 站位（`已證實`）

任務地點的站位直接取記錄：12 個敵人 Y、12 個敵人 X、6 個隊員 Y、6 個隊員 X。
隊伍占參戰者陣列的前六個位置，敵人接在後面，最多 18 名。

### 5. 回合：規劃與執行兩段（`已證實`）

一個回合分成規劃與執行，各排一次順序。**規劃**的鍵值：

```
基準 = (等級 − 1) × 10 + 洞察
隊員在同一回合重排過時：基準 ÷= 2 × 本回合重排次數   ; RE-145
疲勞比例 = 50 × 疲勞 ÷ (力量 ＋ 健康)    ; RE-129～131 訂正早期傷勢解讀
基準 −= 基準 × 疲勞比例 ÷ 200
鍵值 = rand(1…100) + 基準           空位固定 0x7FFF
```

依鍵值由小到大排（相同鍵值維持原本先後），**從小的開始規劃**——
洞察低的先決定、洞察高的後決定。輪到誰就把指令、攻擊選項與防禦選項
記到那一名身上。

**原版的確認方式**（`已證實`，RE-158）：選一個指令、寫回三格之後（`0x1FA6D`），畫面回到
**同一名**的指令列並顯示剛寫的摘要（`loc_1F16A`），可以再選別的；按第一格 YES（圖號 7）
才設 `+0x22`、換下一名（`0x1F38D`→`loc_1FAC4`）。`+0x25` 跨回合保留（隊員那一側
回合收尾不清），所以新回合直接按 YES 就是重複上一回合的指令；什麼都沒選就按 YES，
這一回合的指令碼就是留著的那個值。`sub_11722` 在 Return 時把白框歸零，所以回到指令列
時白框停在 YES。remake 照做（使用者 2026-09-29 決定，RE-160）。

其中：

- 等級：隊員是四列武器的攻防原始值加總 ÷ 1000 ＋ 1；任務地點的敵人用記錄裡的等級。
- 洞察：隊員取角色記錄 0x21，敵人取怪物記錄 +0x13。
- 昏迷門檻 ＝ (體型 ＋ 健康) ÷ 2；六個部位的血量是門檻的 15、15、20、20、30、30 %
  （頭、胸、右臂、左臂、右腿、左腿）。頭或胸被打到 0 就退出戰鬥。
- 隊員開場的累積傷害是角色記錄 0x1B。

整輪規劃完印記錄 0x108「Begin next round?」，圖示列是 YES、U-TURN，競技場與訓練戰
以外再加一格 0x30（RE-143）。YES 進執行段；0x30 問記錄 0x109 要不要逃，逃走的
兩條路（這一格與執行段後的戰場邊上）見 SPEC-014。
U-TURN 跳回 `0x1EF3A` 重排這一回合：重擲規劃鍵值、排序、本回合重排次數加一（RE-145），不再跑回合結束的法術倒數（RE-143，`Replan`）。

**執行**段另外依快捷排一次，從鍵值大的開始動（RE-080 有完整式子）。
負重與指令時間成本已由後續 RE-084／131 關閉，依下方第 4 節授權實作；
撤銷早期「未解而禁作」條款，不宣稱完整結算已通過正常同狀態驗收。

## 4. 執行順序（`已證實`）

整輪規劃做完、玩家在「Begin next round?」答應之後，**另外排一次順序**
（RE-084）。這一次看的是快捷、負重與指令的時間成本：

```
sub_23683(i)                                 ; 疲勞比例，RE-129～131 訂正
鍵值 = 快捷(+0x09) − 快捷 × 疲勞比例 ÷ 200 − 負重 ÷ 10
時間 = 指令 0x29 → 8；0x27 → 6；0x23 → 1
       其餘查 [0x10B2 + 攻擊選項]，而且攻擊選項為 1 時再 ÷ 2
鍵值 −= (武器速度 ÷ 2) × 時間 ÷ 10
鍵值 += 擲骰(100)，負數夾成 0
射擊而且武器種類不是 0x12／0x16 → 再 ÷ 2
```

`[0x10B2]` 是 `00 0f 07 07 07 06 06 06 08 08 08 00 00 02 01 02`。排序是鍵值
小到大，執行迴圈從陣列尾端往回走，所以**鍵值大的先動**；相同鍵值時索引大的先。

原版在移動且攻擊選項為 0 時也算了一次 `÷ 2`，但結果沒有寫回，那一條實際上
不生效（RE-084）。remake 照原版的行為，不實作它。

一手的分派見 RE-084 的表：攻擊（0x21／0x29）在攻擊選項為 0 時指令歸零並印
記錄 0x117；面前那一格沒有人就揮空（徒手 0x11F、其餘 0x120）；有人就走
SPEC-009 的結算，而「面前那一格」用的遮罩只看 +0x1E，**不分敵我**。
休息印記錄 0x119，怯戰把防禦選項設成 2 再印 0x118。怯戰只換這一手（`word_31122`），
記錄的 `+0x25` 不動。

### 回合收尾（`已證實`，RE-158）

所有人出手、第二輪移動（RE-154）都走完之後，`0x20A52` 起依**參戰者索引** 0…N 逐名做：

```
空位（+0x01 == 2）          → 跳過
已退出戰鬥                  → 只做挨傷那一段
疲勞：讀這時的 +0x25（出手之後的指令碼）；休息而且這一回合沒挨打 → 疲勞 × 7 ÷ 10，
      其餘 → 疲勞 −= 花剩的時間額度 ÷ 10（飛著的人負值加倍、正值減半）
      疲勞比例到 100 → 頭與胸清成 0xFF、+0x25 清 0、印力竭那一句
挨傷（0x20E64）：+0x2A = +0x2D；+0x2D = 0；招架次數 +0x0F = 0
法術倒數（0x20F01）
```

所以挨打累計與招架次數是整回合的計數，出手之後才挨的傷也算進這一回合的疲勞。
dosgolem 正常路徑六個回合的執行段（擲骰序列、亂數終態、位置、傷勢、部位、挨傷、
招架、方向、疲勞）與 remake 逐項一致（`TestOriginalNormalRoundsExecution`）。

## 5. 移動（`已證實`）

指令 0x27 與 0x3F 走 `sub_26384`（RE-085）。**一次只走一格，沒有點數也沒有步數
迴圈**——先前把「移動指令 0x27 的點數規則」列為待解，是把移動方式當成了距離。

```
方式 = 攻擊選項 − 0x3C          ; 0x3C…0x40 → 0…4；0x35 落成負數再換成 5
方式 ≥ 3 → +0x1E = 1
新座標 = 自己的座標 + 環 0 的第「方向」項
```

走不動的四種情形，依序判：

1. 目的地那一格擋路（位元圖 `[0x0FC8]`＝`00 10 9a ff f1 ff 17 ff d0 7f`，
   與擋視線的 `[0x10CE]` 是**不同的兩張表**）。+0x1E 非零時只有磚
   0x20…0x22、0x2E 與大於 0x37 才真的擋得住。
2. +0x1E 非零而且腳下那一格的磚是 0x0C。
3. 目的地站著人：+0x1E 為零的擋為零的、非零的擋非零的（遮罩 8 與 4）。
4. 新座標任一軸落在 4…0x3B 之外。戰場陣列 64×64，可走的只有中間那一塊。

走不動印記錄 0x10A，走了一步印 0x10B。移動方式除了設 +0x1E 之外不影響距離，
在執行段的鍵值裡時間成本固定是 6。

## 6. 訊息（`已證實`）

執行段每一手的訊息先進緩衝區再一次排版（RE-087）：`sub_1C1A4` 開緩衝、
`sub_2687F` 印行動者的名字、`sub_1A8FD` 把記錄的內容送進去、`sub_1C1BF` 斷行
並畫出來。所以畫面上那一整句是「<行動者的名字> <記錄展開>」。

版面固定在 byte 欄 3（像素 24）、掃描列 0xA8，行高 6（小字型 8×6）。斷行從
行寬處往回找空白，第一行 30 個字元、之後每行 33 個。EGA小字出口逐字覆寫
8×6白底再畫黑字，包含空白；行尾以外保留底圖。RE-252勘誤：8×8矩形是交疊檢查，
並非清底，模式0D的實際出口為sub_1CE04。來源定位見下方RE-252。

代換碼見 RE-086。攻擊那一手分兩句、各等一次鍵（RE-088）：

```
第一句  動作 ＋ 結果
        武器 [0x12F + 攻擊選項] ＋ 0x13A；徒手 [0x127 + 攻擊選項] ＋ 0x127；
        射擊 0x125／0x126（種類 > 0x7F）＋ 0x127
        落空 → 幅度 > 0x1E 印 0x13B、> 0x0A 印 0x13C、否則 0x13D
        被擋 → 0x15E ＋ [0x15F + 招架碼]；射擊被擋是 0x13F
        命中 → 0x13E
第二句  0x140 ＋ [0x141 + 種類] ＋ 0x143 ＋ [0x144 + 部位]，再依結果接
        傷害 0 → 0x14A；倒下 → 0x14B ＋ die／collapse／shatter；
        手腳廢 → 0x152；頭胸廢 → 敵人 0x151／隊員 0x150；
        其餘 → 0x153 ＋ serious／terrible／grievous ＋ 0x154
```

招架碼查 `[0x11B2 + 11 × 目標防禦選項 + 攻擊選項]`，訊息基底是 **0x15F**；
碼為 4 而且目標體型減行動者體型大於 100 時改成 2。

## 7. 一場戰鬥怎麼結束（`已證實`）

證據見 RE-091。

### 每一輪之後數兩個數

每個回合的執行段走完就掃一次全部參戰者，分別數**倒下的隊員**與**倒下的敵人**。
原版跳過兩種格子：參戰者記錄 `+0x01` 等於 2 的，以及 `sub_22866` 回 0（還站著）的。
remake 用 `Side == SideEmpty` 表示前者，用 `Actor.Down()` 表示後者。

`sub_22866(i)` 看的是參戰者記錄 `+0x11` 與 `+0x13`——頭或軀幹任一為 `0xFF` 就算
倒下（RE-096）。remake 的 `Down()` 判 `Head <= 0 || Chest <= 0`，同一件事。
戰利品那張清單也用同一支挑候選：倒下的人領不到東西。

### 四個結束條件，依序判斷

| 順序 | 條件 | 結果 |
|---:|---|---|
| 1 | 倒下的隊員 ＝ 隊伍人數 | 打輸 |
| 2 | 倒下的敵人 ＝ 敵人數 | 打贏 |
| 3 | 倒下的隊員 ＝ 0 | 繼續打 |
| 4 | `word_345DE` ≠ `0xFFFF` | 有人升級 |

**順序有意義**：打輸排在打贏前面，所以兩邊同時全倒時算打輸。

0x2120C退word_345E0後寫ES；CYCLOPS實際成CYCLOPES。
正常戰敗圖及完整bytes見[RE-256](../re/20261005-monster-plural-ending.md)。

1. 印記錄 **0x174**（`You have defeated|F`），敵人數大於 1 再補英文複數
   （名字以 `S` 結尾補 `ES`、否則補 `S`）與 `!`，等一次鍵。
   中文的譯文自己處理掉了複數，所以只有英文模式補。
2. 金冠：每一隻怪擲「骰數 ＋ 1」次，骰數是怪物記錄 `+0x0F` 的高 nibble 取低三位，
   骰面查 `[0x00D4]` 的 `2 3 5 7 9 11 19 99`。總額除以隊伍人數，**每人不到 2 枚就
   一枚都不給**。
3. 隊伍人數大於 1 才印記錄 **0x175**（`Each player]`），再印 **0x177**
   （`|N gold crowns!`），`|N` 是每人的金額。

### 冒險點數與金冠（`已證實`）

證據見 RE-096。獎勵只在 `word_345DE == 0xFFFF` 時發；戰鬥初始化就是這個值，
所以野外戰鬥一定發。

```
冒險點數：Σ 每一個參戰敵人（怪物記錄 +0x17 與 +0x19 兩個大端 16-bit）÷ 2 ÷ 隊伍人數
金冠：    骰數 = (第一隻怪的 +0x0F ÷ 16) & 7
          骰面 = [0x00D4 + (+0x0F & 7)]        ; 2 3 5 7 9 11 19 99
          總額 = Σ 敵人等級 輪：Σ 骰數 + 1 次：rand(骰面)
          每人 = 總額 ÷ 隊伍人數，不到 2 就歸零
```

金冠的輪數是 `word_3B26A`，也就是**這一場敵人的等級**（RE-097）：隨機遭遇與任務
地點都在進戰鬥前把它設好，而 `sub_1E3A8(0)` 會跳過那一段預設值。等級越高金冠越多。
**注意它和參戰者記錄那一格的等級是兩個尺度**——後者是 `word_3B26A ÷ 5 ＋ 1`
（上限 5），規劃鍵值與敵人 AI 的權重用的是後者。

兩處容易弄錯的地方：冒險點數**不看敵人死了沒**，站上場就算，而且用的是記錄裡的
原值，不是讀技能時再乘等級的那一份；金冠的外層輪數是 `word_3B26A`（野外戰鬥恆為
1），**不是敵人數**，而且骰式只讀第一隻怪的。

那兩句話：隊伍人數不等於 1 印記錄 **0x175**（`Each player]`），等於 1 改逐一印
在籍角色的名字；接著 **0x176**（`receives|N adventure points, and`）與
**0x177**（`|N gold crowns!`）。兩個 `|N` 讀的是同一個變數，原版在印之前各設一次，
所以要分兩段展開。

## 8. 敵人那一手（`已證實`，部分授權）

證據見 RE-081（決策樹）、RE-092（預設權重表）與 RE-159（怪物自帶權重、移動三式、
兩次智力骰、攻擊式的情境列號）。同狀態對拍：`TestOriginalNormalEnemyPlanning`
（[六回合收據](../verification/battle-rounds-parity-20260928.md)）。

### 開頭兩次智力骰

AI 一進場擲 `rand(100)` 存進 `word_3AC5E`（`0x237A6`），找目標遮罩 0x10 整支決策共用
這一次。反制掃描前另擲一次 `rand(100)`（`0x23C1A`）做智力檢定，過關才掃。

### 主幹

```
兩隻手臂都廢          → 移動
環 0（八個相鄰格）找隊員
    找到 → 攻擊（指令 0x21）；+0x00（SPEC-029 的遠程能力值）非零的怪物擲 rand(3)，
           1 就改成移動（為 0 的不擲，`0x23CA7`）
    沒有 → 往外掃環 1…6
        看得見、環號 < 4、有武器又有右臂 → 射擊（指令 0x23）
        否則 → 朝目標走一步
七環都沒人            → 隨機挑一個站得下的方向移動
```

環的半徑是**環號 ＋ 1**，格數 8R；起點 `(−R, 0)` 沿邊順時針。搜尋的**起點是隨機的**
（`rand(格數 − 1) − 1`），所以同樣的戰況不會總是選同一個目標。

### 三張基礎權重表

戰鬥初始化 `sub_1E3A8:0x1EC49` 看怪物記錄 `+0x1A0`：非零就抄記錄 `+0x1A0`（攻擊式 10 筆）、
`+0x1AA`（部位 7 筆）、`+0x1B1`（移動三式 3 筆）；為零才用 DGROUP 的預設表：

| 表 | DGROUP | 預設內容 |
|---|---|---|
| 攻擊式 | `0x1092` | `6 6 5 4 6 4 4 6 6 5` |
| 部位 | `0x10A6` | `1 3 4 4 4 4 2` |
| 移動三式 | `0x10AE` | `12 24 72` |

32 隻怪物裡只有 MUCK THING 與 LIZARION 的 `+0x1A0` 是 0，走預設表。

### 移動三式（`0x239D7`…`0x23BB9`）

```
w = 移動三式權重（步行、奔跑、衝刺）
兩腿都 < 0x80 且環號 < 7 → w[2] = 0
否則：環號 < 2 → w[2] /= 2；疲勞比 > 0x31 → w[2] /= 2
      w[2] = w[2] × 額度 ÷ 花費 × 額度 ÷ 花費     ; sub_251B0(6, 0)，16 位元
總和 s（0 當 1）；w[2]、w[1] 各乘 255 ÷ s（索引 0 不動）
r = rand(256) − 1，從索引 0 起逐項扣，扣成負的就選中，兩項都沒扣完就是 2
攻擊選項 = 0x3C + 選中；選中 0 防禦選項 2，否則 0
```

索引 0 沒有正規化，三項加起來不到 255，所以衝刺那一項歸零時，擲到尾端的仍會選衝刺。
沒有等級加權。

### 加權輪盤

攻擊式與部位共用 `sub_25A3A`：

```
w = 情境權重^等級 ÷ 2^(等級−1)      ; [0x10C6]
acc[i] = w × 基礎權重[i]
正規化成總和 255，擲 rand(256) − 1 逐項扣，扣成負的就選中
```

情境權重是 `[0x0FF4]` 的 16 列 × 10。抽攻擊式時列號是 `word_30916`：環 0 那條是 7
（`0x23CA1`）；反制掃描那條由 `sub_253E7` 帶回，對方還沒規劃是 7，其餘是對方的防禦
選項 `+0x24`。抽部位時列號換成攻擊式。攻擊選項最後要**加二**，超過 10 退回 1
（`0x23CEE`）。

攻擊式的情境權重再乘遮罩：前 8 筆是 `[0x109C + i]` 與怪物記錄 `+0x2D` 有交集算 2、
沒有算 1，乘積存成一個 byte；第 8、9 筆原版沒有寫，讀到的是共用緩衝 +0x28／+0x29 的
殘值：上一次打開旅店名冊清單時第 8、9 名的槽號，清單不夠長就更早的值，程式啟動時是 0
（RE-159）。remake 照做：`town.Session.RosterListTail` → `State.StyleMaskTail`，只存在
記憶體。

等級越高越偏向權重高的選項，低等級的接近均勻亂選——這是原版把「聰明的怪物」
做出來的方式。

### 授權實作的範圍

上面三節都授權實作。**撤退、反制掃描與側翼也授權了**：`+0x29`（撤退狀態）、
`+0x2A`（上一回合挨的傷）、`+0x2D`（這一回合挨的傷）與 `+0x22`（這一回合規劃過了沒有）
的語意與 writer 都已解出，兩個撤退門檻在怪物記錄的 `+0x0D`／`+0x0E`（RE-081）。
找目標的篩選遮罩 0x10：智力骰過關的敵人看不到 `+0x05` 非零（戴 Shade Ring）的隊員，
反制掃描、往外環找目標與撤退時的相鄰檢查都套用（RE-154）。

**部位與攻擊式的兩個權重修正也接上了**（RE-131）：`word_30D06` 是這一手的時間額度、
`word_2F940` 是 `sub_251B0(a, b) = a × 武器速度 + b × 負重`，`sub_2526C` 把
「額度 ÷ 花費」夾進 1/3…1。攻擊式那一支（`sub_2578F`）拿 `sub_251B0(15, 1)`，
把最後一項乘上那個比值（只會壓低）；部位那一支（`sub_2590F`）拿
`sub_251B0([0x10B2 + 攻擊選項], 2)`，把索引 < 2 與 == 6 那三項乘上**倒數**
（1…3 倍），而且額度用的是完整那一份（`0x2596C` 先設回 `word_2FBB6`）。

**隊員**徒手那四式拿的是**穿戴品**，不是手上那件（`UnarmedSlots`，RE-131）：踢用
FEET、盾擊用 SHIELD、頭槌用 HEAD、拳用 HANDS，位址是角色記錄
`+0x100 + [0x0FD2 + 選項]`。

**怪物不走這條路。** 四式的 `var_4` 一律指向本體記錄 `+0x20`（武器），把那一格整格
清零（真正的赤手空拳）也不改變；同一份探針對隊員跑正對照，四式各自落在四個不同的
槽，所以這不是探針沒走進徒手分支（2026-09-10 讀取監看，
[那幾格根本沒被讀](../re/20260910-monster-unarmed-slots.md)）。怪物記錄 `+0x30` 起
那幾格是穿戴欄這件事沒有問題——護甲三件與盾牌就在裡面，照常使用——不成立的只有
「徒手時會去取那幾格」。

沒有武器時的指令 0x26 已由 RE-116 授權並實作；不再列入早期禁作清單。
