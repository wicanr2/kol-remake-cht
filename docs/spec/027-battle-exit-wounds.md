# SPEC-027：戰鬥共同出口傷勢回寫

狀態：**READY**（2026-09-08；同日 DRAFT 經下列直接證據審查）。

IDA Pro 9.4 線性位址 `sub_1E3A8:0x2186E..0x218E8`，輸入
`KOLTOWN-unpacked.EXE` SHA-256：
`01f6f9a95c4adf8e9da59fa83bae57aa282e5576767b41bfc2f23302aeb9d1d2`。
匯出 `workplace/battle-exit-20260908/battle-exit-private.json`；
探針 `tools/ida_probe_battle_exit.py` 保留原始名稱、位元組及地址，未改名。

正式契約：走訪前六個參戰者，只處理 `+0x01 == 0` 的隊員。
角色原傷勢讀自 `[word_39A48+0x1B]`，戰中累積傷勢讀參戰者 `+0x0E`；
兩者先作 16-bit 減法，再以無號除法除二，低位元組加回角色原傷勢。
不得將戰中累積傷勢直接當作戰後值。未參戰觀眾不回寫。

本段在一般勝利、撤退、敗北與競技場結算的共同出口。
`TestBattleExitWoundsOriginal` 以 dosgolem 真實執行 `0x2186E` 至函式返回：
六個初始傷勢邊界 × 256 個戰中值 × 三種陣營，共 4608 組通過。
入口橋只建立堆疊；`sub_22278` 替換為可觀察的角色取址，折算、六槽迴圈、
陣營跳過與寫回均為原版指令，沒有 RND 呼叫。原始通過收據在
`workplace/battle-exit-20260908/oracle/`。不能把純資料計算宣稱為正常玩家路徑。

READY 審查：`0x218C5` 為 16-bit 減法，`0x218CA` 清 DX 後 `div`；
`0x218D8` 只加 AL 至角色 byte，須保留無號與低位元組行為，不自行夾零。
平常沒有溢位時，例如原傷勢 5、戰中 24，戰後為 14。
角色／傷勢門檻以原版比較為準，不能只在勝利或撤退回寫。

護甲及物品在原版戰鬥中直接修改角色記錄（SPEC-017、RE-094／127），
共同出口未還原這些修改；敗北也必須保留已發生的傷勢、裝備耐久與交換結果。
本次不新增未知掉落機率或猜測額外扣錢。敗北的掉落／世界完整路徑仍未關閉。

實作及驗收：核心傷勢計算與 4608 組原版結果直接比較，正式出口接線，
勝利／撤退／敗北／競技場勝敗至 v2 重載，並驗觀眾不被改寫。
未完成正常原版與重製完整戰鬥鏈前維持 READY，不升 CONFORMED。
