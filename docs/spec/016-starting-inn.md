# SPEC-016：開場旅店接線

狀態：**READY**；授權實作範圍為已載入城鎮的角色選隊與旅店流程整合。

2026-09-08 後續接線審查：跨城所需的城鎮代碼、入口、鏡頭與邊界已有 RE-069 及
`town.EnterFromWorld` 契約，建築與格子由既有 typed data／PNG 載入。據此將跨城接線
由待辦草案審查為 READY：依唯一城鎮代碼取完整入口，先載入建築與地圖，在暫存狀態
驗證角色旅店與可還原座標後才一次切換；失敗不得改動現行隊伍、戶外指標或地圖。
從野外進城也必須同步該入口的城鎮代碼，不能保留前一城的招募篩選值。
此段取代下方「跨城載入待完成」的實作範圍限制；同狀態對拍仍待驗證。

## 證據審查

- 已證實：正常 `KOL.EXE → KOLBOOK.EXE → KOLTOWN.EXE` 選擇 Theodoric 後進入
  Halfway House。輸入雜湊、工具與重跑入口見 `docs/re/20260908-kolbook-input-bridge.md`。
  原版 `book-final.png` 顯示該旅店與內部操作列。
- 已證實：角色 `building_id` 與所在地欄對應留宿建築，見 SPEC-006 及 RE-073。
- 既有建築流程依 RE-067、RE-072、RE-073 執行對話、招募與住宿。開場使用同一個
  `town.Session`，不得用只支援 DOOR 的靜態畫面取代。

## 接線契約

1. 名冊選角先驗證角色城鎮代碼、建築編號與所在地名稱能對應目前載入的城鎮建築；
   找不到或資料不一致時保留選角頁與原有隊伍，記錄缺口，不猜建築、不進靜態樣本。
2. 成功後建立獨立隊員副本，將戶外位置置於該建築門格，經正式建築初始化進入室內。
   此為開場角色所在地還原，不是測試用座標注入。離店仍使用既有清門口狀態流程。
3. 後續輸入與繪製交給同一個 Session；對話分頁、招募、住宿及離店不能再由 flow
   維護另一份只處理 DOOR 的狀態。中文資料頁仍是已登記缺口，不因本接線宣稱完成。
4. 跨城選角由上層提供唯讀載入器載入正確城鎮與邊界（`recruit.go`，收據
   `docs/verification/cross-town-fix-20260908.md`）；所在地無法對應時保持原狀。
   同一個代碼可有多個入城點（TOWN7 十個都是 MIN），各帶不同鏡頭與夾限：目前的
   入城區放不下旅店門口時，依所在地代碼逐一試入城點，取第一個放得下的。原版挑入城點
   的規則沒有讀過，這個順序是 remake 的選法，只影響之後走路的夾限範圍（屬 remake 決定，
   不是原版證據）。
   本規格不改保存 schema、住宿設定或任何建築規則。

繁中清單沿用既有對話框與 16 px 字型，八列各 16 px；白色選中列、青色其他列，
捲動指示保留於右側。名稱不翻譯，超寬逐字截斷，不能畫出安全矩形。
這補足英文版已存在的清單呈現，不改候選人排序、選擇與招募規則。

招募清單的滑鼠列選擇依使用者已核准的等價操作原則：點候選人列應送出對應上下移動、
移回確認圖示及 Return，不能把點擊其他列當成確認目前反白者。只使用現有鍵盤狀態機，
不直接改游標、跳過搜尋問句或繞過隊伍容量限制。中英文依各自實際繪製行距建立可點區域。

## 驗證閘門

正常 flow 輸入從標題到選角、旅店招募、離店；確認室內／戶外共用同一隊伍及正確門格。
不一致所在地必須保留選角狀態。回歸通過只證明接線，GUI、AppImage 與原版同狀態驗證
另行執行；未完成前不標為 CONFORMED。

## 2026-10-01：城門邊界的繁中繪圖補齊

此子契約由繪圖缺口草案經證據審查進入 READY，再於下列顯示驗收通過後標為
**CONFORMED（限重製版繁中繪圖）**；只修正已載入城鎮的
繁中顯示，不改輸入、行走規則、城門選項、角色資料或保存格式。

- **已證實**：固定 `KOLTOWN-unpacked.EXE`，SHA-256
  `01f6f9a95c4adf8e9da59fa83bae57aa282e5576767b41bfc2f23302aeb9d1d2`；
  IDA Pro 9.4 的 KOLTOWN 線性位址空間中，`sub_1198E` 在
  `word_2FBC2 == 0FFFFh` 時使用 `sub_1103F(22h)`，即 `MISCPICS[0]`。
  原始定位與狀態轉移見 [RE-065](../re/RESEARCH-LOG.md#re-065城鎮地形擋路地圖邊界的城門提示以及圖示列的生命週期)
  及 [城鎮證據索引](../re/town-and-world.md#城鎮)。
- **既有輔助基準**：原版 DOSBox-X 的城門畫格與英文重製收據見
  [城門對拍計畫](../verification/remake-parity/plan-town-edge.json)、
  [正常玩家按鍵路徑](../verification/player-path/town-edge.json)。這些不是
  新重生的 dosgolem 收據，也不宣稱繁中版面逐像素等同原版。
- **輸入與輸出**：`town.Outdoor.AtEdge` 為真時，以既有 `EdgePicture`
  指向的 PNG 填入 `CJKOutdoor` 地圖視窗，最近鄰放大三倍，再畫正常城門圖示。
  此分支優先於建築門面與磚塊圖；不畫隊伍地圖標記。缺少 PNG 時回傳原有素材錯誤，
  不猜替代圖。非邊界的門面與地圖沿用現行顯示。
- **垂直鏈**：已驗證 PNG → `Sprites.Get` → `OutdoorCJK`；行走／城門的
  `town.Session` 與存檔契約不變。測試須確認繪圖不回寫戶外狀態。
- **驗收**：從標題、名冊、旅店以正常按鍵抵達邊界，固定 remake seed 1；
  核對英中逐步狀態、城門與 U-TURN 畫格，以及地圖視窗對來源 PNG 的三倍像素。
  另抽驗建築門面、返回地圖與出城，並保留修補前收據；不得以孤立繪圖測試取代此路徑。
  本次只核實既有原版證據所定的顯示契約，不擴張整場遊戲或亂數原版對拍聲明。

驗收結果見 [正式收據](../verification/cjk-ui/town-edge-20261001/receipt.json)：
