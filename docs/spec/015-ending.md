# SPEC-015：結局

狀態：**READY**（觸發那一格的來源除外）  
證據：RE-106（`sub_2B4A7` 逐條、`0x2B36B`…`0x2B3A9` 的觸發）、RE-017（七張 ENDPICS
的來源與幾何）、RE-063（ENDTXT 的版面）  
授權實作：七段的圖、文字、矩形與推進**是**；觸發條件的接線**否**——
`[0x1DD]` 那一格是誰寫的還沒解

## 1. 什麼時候播（`已證實`）

結局接在**任務戰鬥打完之後**（`sub_2B0FF` 的尾端）：

```
sub_1E3A8(0)                                  ; 打這一場
word_34968 != 0xFFFF → 跳過
逐一走六名角色（一筆 0x300）：
    角色記錄[+0x00] 為零 → 這一格沒有角色，下一位
    角色記錄[0x1DD + word_2DF70] == 0x17 → sub_2B4A7()
```

`word_34968 == 0xFFFF` 是 `sub_28F5D` 標任務完成時設的（`0x28FC4`，RE-101）——
**沒標到就不檢查**。

判準那一格在任務旗標區（`0x1E2`）前面五個 byte，群組偏移與旗標共用
`word_2DF70`。**為什麼是 0x17 還沒解**：任務地點編號是 0…23，「完成到最後一個」
是合理的猜測，但沒有對到寫入點，證據等級只到 `假說`。原版十四名角色的那一格
全是 0（`assets/original-derived-data/character-roster.json` 的 `progress`）。

## 2. 七段（`已證實`）

`sub_2B4A7` 是一條直線。每一段：清畫面、設矩形、畫圖、印記錄、等一個鍵。

| 段 | ENDPICS 圖號 | ENDTXT 記錄 | 矩形（左欄, 上列）–（右欄, 下列）| 像素 |
|---:|---:|---|---|---|
| 0 | 0 | 0、1 | (1, 13)–(22, 135) | 168×122 |
| 1 | 1 | 2、3 | (15, 41)–(39, 152) | 192×111 |
| 2 | 2 | 4、5 | (1, 50)–(38, 143) | 296×93 |
| 3 | 3 | 6、7、8 | (1, 50)–(23, 147) | 176×97 |
| 4 | 4 | 9、0x0A | (17, 12)–(38, 135) | 168×123 |
| 5 | 5 | 0x0B、0x0C、0x0D | (0, 46)–(24, 148) | 192×102 |
| 6 | 6 | 0x0E、0x0F、0x10 | (16, 45)–(39, 143) | 184×98 |

四個全域是矩形的四個邊（`word_3499E` 左欄、`word_349A0` 上列、`word_34A06`
右欄、`word_34A0E` 下列）。**欄乘八得像素**；右欄減左欄乘八與下列減上列，
與 RE-017 從像素數反推的七組尺寸**全部吻合**——這是四個全域語意的交叉驗證。

ENDTXT 有 18 筆，這裡用掉 17 筆（0…0x10）；**最後一筆沒有任何呼叫點**。

## 3. 文字怎麼擺（`已證實`）

敘事自帶 `~Vxx`／`~Hxx` 定位（記錄 0 開頭是 `~V08~H17`），擺在圖的哪一側由文字
自己決定，程式不另外算。

**一段的兩三筆要接成一整段再拆座標**：原版是逐筆送進同一個緩衝區的（RE-088），
第二筆開頭那幾個字接在第一筆的最後位置。分開解析會把它當成新的一段畫到左上角
——實作時踩過這個坑，`town.JoinedSegments` 就是為此加的。

## 4. remake 的落點

`internal/ending`（七段的資料、矩形換算、觸發判準、播到第幾段），
`internal/ui/ending.go`（畫圖與文字），`cmd/kol` 的 `sceneEnding`。
`tools/extract_character_roster.py` 多帶一個 `progress` 欄位，就是 `[0x1DD]`
起那五格。

**還沒接的是觸發**：`progress` 還沒進 remake 的存檔與 `town.Member`，
所以目前只能用 `-scene ending` 直接播。等 `[0x1DD]` 的寫入點解出來再接，
免得照著假說接出一條永遠不會成立（或永遠成立）的路。

實跑收據 `docs/verification/ending/` 七張畫格。
