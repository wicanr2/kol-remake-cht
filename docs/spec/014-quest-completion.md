# SPEC-014：任務的完成與逃走

狀態：**READY**（掉東西那一段與競技場的升級除外）  
證據：RE-101（`sub_28F5D` 逐條）、RE-103（`0x21045` 的逃走判定與 `sub_2886C`）、
RE-079（旗標的讀取端）  
授權實作：旗標的標記、逃走的條件與那一問**是**；掉東西、競技場的升級**否**

## 1. 旗標放在哪（`已證實`）

```
起點  = 6 × word_2DF70 + 0x1E2          ; 角色記錄裡，一組六個 byte
byte  = 起點 + 任務地點編號 ÷ 4
除數  = [0x7C + (編號 & 3)]             ; 1 4 16 64——一個 byte 塞四個 2-bit 欄位
值 ÷ 除數 & 3： 1 = 接了、2 = 完成
```

讀取端是 `sub_2B0FF:0x2B108`（有人的欄位等於 1 才踏得上那個地點，RE-079），
寫入端是 `sub_28F5D`。

remake 的 `Member.Quests` 只存一組六 byte，等於把 `word_2DF70` 固定在 0——原版
`CHARDATA` 裡的三名帶旗標角色都落在這一組，還沒看到會換組的路徑。

## 2. 什麼時候標成完成（`已證實`）

`sub_28F5D` 有兩個呼叫點，都在戰鬥主迴圈裡：

| 呼叫點 | 前置條件 |
|---|---|
| `0x211CB` | 擊倒數等於怪物總數，也就是**打贏** |
| `0x21176` | 玩家答應**逃走**而且 `word_39A54 != 0` |

**只有任務戰鬥會做**：`0x28F66` 先看 `word_34968`，是零就整支跳掉。隨機遭遇把它
設 0（`sub_2A4E5:0x2A82B`）、任務地點設 1（`sub_2B0FF:0x2B1AD`）；remake 用
`Site.Index >= 0` 表示同一件事。

**六名角色一律走完**，不看誰在隊上、也不看誰在場（`0x28FEF` 一筆 0x300）。

**沒接那個任務的人也會被標**：`0x28FB9` 只比 bit 1，值為 0 的落在「不是 2」那一邊，
照樣被寫成 2。寫法是「先 `and` 掉那一位、再 `or` 上它的兩倍」（`0x28FCD`）。

打贏那一條的順序是：先標旗標，再印記錄 0x174，之後才是冒險點數與金冠（RE-096）。

## 3. 逃走的條件（`已證實`）

執行段走完、還沒分勝負時（RE-091 的四個判斷都不成立）落到 `0x21045`：

```
word_3AC5A = 0 ; word_39A54 = 0
對六名參戰者：
    不是隊員（+0x01 != 0）跳過
    +0x1F 或 +0x20 等於 4 或 0x3B 才算數      ; 站在可走區的最外圈
    word_3AC5A += 1
    sub_22278(i) ; sub_2886C(0x30) 非零 → word_39A54 += 1
```

可走區是 4…0x3B（RE-085），所以條件是**腳踩到最外圈**，兩軸任一個到邊就算。
倒下的人不排除——這一段只比 `+0x01`。

問不問：

| 條件 | 結果 |
|---|---|
| `word_39A54 != 0` | 問 |
| `word_3AC5A == word_2DF2A`（全隊都到邊上）| 問 |
| 兩個都不成立 | 不問，直接排下一回合 |

問的是記錄 **0x109**（`Do you want to flee?`）。**只認 `y`／`Y`／`n`／`N`**，
其餘的鍵重問（`0x21149`…`0x21198`）。

**0x109 不接在 0x108「Begin next round?」之後**——RE-079 最初的敘述有誤，已訂正。

## 4. `sub_2886C(位移)` 是名字比對（`已證實`）

```
word_34968 == 0 → 回 0                        ; 隨機遭遇一律不算
word_39A48[位移 + i] 與 [0xB926 + i] 逐 byte 比，i 走 0…15，全同才回 1
```

位移 0x30 是角色記錄裡**手上那件東西的名字**（RE-086 的 `|E` 讀的就是這一格）。
`[0xB926]` 那十六個 byte 由誰填還沒解——它是被整塊複製寫進去的，operand 掃描
（`tools/ida_probe_koltown_writers.py`）一次命中都沒有。

remake 用 `State.QuestItem` 承接，空字串表示這一場沒有那樣的東西。

## 5. 帶著東西逃掉也算完成（`已證實`）

答 `y` 而且 `word_39A54 != 0` 時 `0x21176` 呼叫 `sub_28F5D`。也就是說
**任務不必打完**：搶到那件東西、走到戰場邊上、逃掉，一樣記完成。

逃走之後從 `0x211AD` 走戰鬥的共同出口；`word_345DA` 與 `word_34966` 同時等於
0xFF 時印記錄 **0x17B** ＋ **0x17C**／**0x17D**（單複數看隊伍人數）。
**兩個計數怎麼變成 0xFF 還沒找到寫入點**，所以 remake 用自己的 `VerdictFled`。

## 6. 實跑收據

`docs/verification/battle-flee/`：問句與收尾兩張畫格，走的是「全隊都到邊上」
那一條（`State.QuestItem` 這一次是空的，因為 `[0xB926]` 還沒解）。

那一次實跑補上兩處畫面層的缺口：逃走那一問原本沒有畫在執行段的卷軸上
（`Plan.Prompt` 是新的一層，UI 沒接），答應之後也沒有印「You flee for your
life!」就直接回野外。兩個都是單元測試看不到的——規則層回傳值正確，
畫面上什麼都沒有。

**替代輸入的坑**：第一次跑的時候換了站位，畫面卻與沒換的逐 byte 相同。原因是
那個 seed 在野外那七十步先觸發了伏擊，走到的是隨機遭遇——站位用固定表
（RE-098），地點自帶的座標根本沒被讀。換 seed 才走得到任務地點。

## 7. remake 的落點

`victory.go` 的 `QuestTaken`／`MarkQuestDone`／`markQuestDone`，
`flee.go` 的 `OnFieldEdge`／`FleeOffer`／`OfferFlee`／`Flee`，
`execution.go` 的 `Step` 在 `VerdictWon` 的第一件事，
UI 是 `PromptFlee` ＋ `StageFlee`。

**還沒做的**：逃走或落敗之後掉東西那一段（`0x21765`，要先有裝備欄十二格的
typed data），以及升級——`word_345DE` 只有競技場 `sub_2AAA8:0x2AFE6` 會寫進真值，
所以那一段歸競技場，不放進戰鬥模組（RE-103）。
