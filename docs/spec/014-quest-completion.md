## 1. 旗標放在哪（`已證實`）

```
起點  = 6 × word_2DF70 + 0x1E2          ; 角色記錄裡，一組六個 byte
byte  = 起點 + 任務地點編號 ÷ 4
除數  = [0x7C + (編號 & 3)]             ; 1 4 16 64——一個 byte 塞四個 2-bit 欄位
值 ÷ 除數 & 3： 1 = 接了、2 = 完成
```

讀取端是 `sub_2B0FF:0x2B108`（有人的欄位等於 1 才踏得上那個地點，RE-079），
寫入端是 `sub_28F5D`。

remake 的 `Member.Quests` 只存一組六 byte，等於把 `word_2DF70` 固定在 0——原版
`CHARDATA` 裡的三名帶旗標角色都落在這一組，還沒看到會換組的路徑。

## 2. 什麼時候標成完成（`已證實`）

`sub_28F5D` 有兩個呼叫點，都在戰鬥主迴圈裡：

| 呼叫點 | 前置條件 |
|---|---|
| `0x211CB` | 擊倒數等於怪物總數，也就是**打贏** |
| `0x21176` | 玩家答應**逃走**而且 `word_39A54 != 0` |

**只有任務戰鬥會做**：`0x28F66` 先看 `word_34968`，是零就整支跳掉。隨機遭遇把它
設 0（`sub_2A4E5:0x2A82B`）、任務地點設 1（`sub_2B0FF:0x2B1AD`）；remake 用
`Site.Index >= 0` 表示同一件事。

**六名角色一律走完**，不看誰在隊上、也不看誰在場（`0x28FEF` 一筆 0x300）。

**沒接那個任務的人也會被標**：`0x28FB9` 只比 bit 1，值為 0 的落在「不是 2」那一邊，
照樣被寫成 2。寫法是「先 `and` 掉那一位、再 `or` 上它的兩倍」（`0x28FCD`）。

打贏那一條的順序是：先標旗標，再印記錄 0x174，之後才是冒險點數與金冠（RE-096）。

## 3. 逃走的條件（`已證實`）

執行段走完、還沒分勝負時（RE-091 的四個判斷都不成立）落到 `0x21045`：

```
word_3AC5A = 0 ; word_39A54 = 0
對六名參戰者：
    不是隊員（+0x01 != 0）跳過
    +0x1F 或 +0x20 等於 4 或 0x3B 才算數      ; 站在可走區的最外圈
    word_3AC5A += 1
    sub_22278(i) ; sub_2886C(0x30) 非零 → word_39A54 += 1
```

可走區是 4…0x3B（RE-085），所以條件是**腳踩到最外圈**，兩軸任一個到邊就算。
倒下的人不排除——這一段只比 `+0x01`。

問不問：

| 條件 | 結果 |
|---|---|
| `word_39A54 != 0` | 問 |
| `word_3AC5A == word_2DF2A`（全隊都到邊上）| 問 |
| 兩個都不成立 | 不問，直接排下一回合 |

問的是記錄 **0x109**（`Do you want to flee?`）。**只認 `y`／`Y`／`n`／`N`**，
其餘的鍵重問（`0x21149`…`0x21198`）。

### 3b. 「Begin next round?」的逃走格（`已證實`，RE-143）

原版還有第二條路：整輪規劃完的 0x108 那一列，在競技場與訓練戰以外多一格 0x30，
選它印 0x109，答 y 全隊一定逃掉；逐名以 `((智力 ＋ 力量) ÷ 2 × 等級) ÷ 3` 當門檻擲
`rand(100)`。手上是武器（種類 byte 高三位元非零）的人，骰大於門檻而且沒有穿 Courage
Coat（`+0x06`），或手上那件就是任務要的東西（第 4 節的 `sub_2886C(0x30)`，與骰無關），
就把武器丟在腳下（RE-154）。原版那一格 `+0x06` 讀的是規劃段留下的 `word_37D2A`，
remake 讀逐名自己的。
這一條直接跳到共同出口 `0x211AD`，**不經過** 第 5 節的 `0x21176`，所以帶著任務物品
從這一格逃走不算完成。答 n 與 U-TURN 相同，回去重新規劃這一回合。remake 的落點是
`NextRoundBar`、`ChooseNextRound` 與 `BarFlee`（`internal/battle/flee.go`）。

## 4. `sub_2886C(位移)` 是完整物品記錄比對（`已證實`）

```
word_34968 == 0 → 回 0                        ; 隨機遭遇一律不算
word_39A48[位移 + i] 與 DS:[0xB956 + i] 逐 byte 比，i 走 0…15，全同才回 1
```

位移 0x30 是角色記錄裡**手上那件東西的完整 16-byte 記錄**。
2026-09-08 以 IDA 9.4 資料庫重查 `0x2888D..0x288BD`：不遇零終止，
也不只看解碼後名稱；同名而狀況等欄位不同亦不相等。舊「名字比對」用語過窄。
`[bx-46AAh]` 對應 DS:0xB956，IDA 線性為 0x39826；舊 0xB926 是位址誤算。
現行 24 個任務均有完整、非零的物品記錄；拾取提示及攜物逃走須共用同一判準。
缺少或損壞的記錄不得退回顯示名稱比對，不新增正式資料格式。
`[0xB926]` 的早期直接 operand 掃描未找到寫入，不代表沒有間接寫入端。
後續 RE-113 已關閉任務 payload `+0x29` 的物品來源；`NewQuest` 使用
`Site.QuestItem`，並依 `sub_2B0FF:0x2B1F0` 的座標把它放到 `Ground[0]`。
保留早期掃描失敗的工具索引，不再把「掃描未命中」當作現在來源未知。

remake 用 `State.QuestItem` 承接，空字串表示這一場沒有那樣的東西。

## 5. 帶著東西逃掉也算完成（`已證實`）

答 `y` 而且 `word_39A54 != 0` 時 `0x21176` 呼叫 `sub_28F5D`。也就是說
**任務不必打完**：搶到那件東西、走到戰場邊上、逃掉，一樣記完成。

逃走之後從 `0x211AD` 走戰鬥的共同出口。出口要 `word_345DA` 與 `word_34966` 同時
等於 0xFF 才印記錄 **0x17B** ＋ **0x17C**／**0x17D**，而 0xFF 只在逃走格答 y 的
`0x1FCF5` 設；戰場邊上答 y 帶著本回合的倒下計數出去，一般戰鬥不印任何一句，直接
收尾（RE-146）。remake 以 `VerdictFled` 表示兩條逃走，`State.FleeLine` 分辨要不要印。

## 6. 實跑收據

`docs/verification/battle-flee/`：問句與收尾兩張畫格，走的是「全隊都到邊上」
那一條：第 5 個地點的任務物品 Kelder Crown 放在地上（`Site.QuestItem`，RE-113），
這一次沒有人撿，所以不是「帶著東西逃掉」那一條。

`docs/verification/player-path/quest-chain.json`：帶著東西逃掉那一條的正常玩家路徑。
從標題接下 Ship Wheel 任務（地點 6），戰場上撿起、走到上緣答 y，六人旗標成為完成；
回 7 號門交付後全隊回報，住宿存檔；`quest-chain-reload` 讀檔重載。

逃走那一問畫在執行段的卷軸上（`Plan.Prompt` 的一層）；答 y 之後直接回野外，
不印逃走那一句（RE-146）。問句沒畫出來這種缺口單元測試看不到——規則層回傳值
正確，畫面上什麼都沒有——所以這一條要靠實跑收據。

**替代輸入的坑**：第一次跑的時候換了站位，畫面卻與沒換的逐 byte 相同。原因是
那個 seed 在野外那七十步先觸發了伏擊，走到的是隨機遭遇——站位用固定表
（RE-098），地點自帶的座標根本沒被讀。換 seed 才走得到任務地點。

## 8. 建築內交付任務物品（2026-09-25 READY 補充）

RE-139 以 IDA Pro 9.4、固定 unpacked EXE 的原始位址與交叉參照複核
`sub_11A93:0x11B5A..0x11D0B`。先前「交付時沒有台詞」已被
`0x11C16/0x11C26` 的直接呼叫推翻。規格僅涵蓋既有任務建築的玩家路徑：

1. 進門先畫訊息 0／1，等玩家按一次 SPACEBAR，之後才檢查
   `icon_flags[1] & 4` 與隊伍的原始 16-byte 物品記錄。沒有吻合物品就繼續
   正常招呼語，不改旗標或物品。
2. 依隊員 0…5、每人 `CarriedOffsets` 由小到大的順序找**第一件**吻合物品，
   在原格換成建築給的 16-byte 記錄。型別化的手持／背包／穿戴物品必須同步，
   不得在下一次保存或戰鬥重新長出已交出的物品。
3. 交換後顯示原版訊息 6＋7 的內容（每槽最多四行；實際非空行數依建築資料），圖示列只留
   SPACEBAR。玩家再按一次，才遍歷所有六名有角色的隊員；**凡此任務旗標為
   「完成」的，不論誰持有交付物，都改成「回報過」並各加一筆已回報數**。
   旗標不是完成者保持不變，但交換仍發生。
4. 一次進門只交換第一件吻合物品。按鍵後回到既有招呼語及建築圖示列；
   同一隊若還有人持有相同物品，必須再次進門才會交換下一件。

驗收：Go 規則與正常按鍵測試覆蓋「非持物者也回報」、「兩人持相同物品只交換第一件」、
「首次 SPACE 前不得回寫」、中文台詞與保存後原件不復活；原版以關鍵點接手比較 8 組
（RE-162），正常玩家路徑見 `quest-chain`／`quest-chain-reload`。
