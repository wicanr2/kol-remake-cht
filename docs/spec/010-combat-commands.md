## 範圍

## 原版行為契約

### 1. 決策欄位與寫回（`已證實`）

一名的決定由三個值構成，收尾一律寫進參戰者記錄：

| 值 | 欄位 | 意思 |
|---|---|---|
| 指令碼 | +0x25 | 選中的圖號（圖示列的命令碼） |
| 攻擊選項 | +0x23 | 子選單換算出來的選項 |
| 防禦選項 | +0x24 | 防禦方式選單換算出來的選項 |

方向（+0x28）由選目標格自己寫。玩家與敵人共用同一組欄位與同樣的寫回順序，
只差寫回點：玩家在 `0x1FA6D`、敵人在 `0x1F104`。決定完成之後 +0x22 設 1。

玩家寫回之後跳 `0x1F16A` 重畫**同一名**的指令列，白框在 YES（`sub_11722` 讀到 Return
時把白框歸零）；按 YES（`sub_228B7` 回 7）才走 `0x1FAC4` 設 +0x22、換下一名。重畫前
依全域 `word_31122`（最後一個寫進 +0x25 的指令碼：隊員寫回、敵人 AI、回合收尾
`0x20A8B` 都會改它）決定要不要在地圖上標出目標格：武器、徒手、施法、移動、騎乘移動與
已上弦的射擊才標；射擊與要選目標格的施法標記住的目標格（出了 0…8 不標），其餘標面向
那一格。2026-10-01 RE-171 續核訂正：有人條件只決定是否重建人物暫存圖；
空格仍畫圓環，見本文「圓環呈現窄契約」。保留 RE-160 原始證據與本次訂正入口。

2026-10-01 摘要來源勘誤（**CONFORMED，限本節來源與窄呈現**）：`0x1F16A` 先呼叫 `sub_249AE`，
該函式 `0x249C5..0x249CB` 由目前人物 `[bx+25h]` 重新載入 `word_31122`，
也重新載入兩個選項；因此主列摘要讀到的是**重建後的目前人物指令**，不能直接沿用
上一名或 AI 留下的值。原「全域最後寫入」說明只描述暫存器，漏追前置重建呼叫。
RE-171-source 保留原定位並追加此訂正；正常 gui7 plan-09→10 換人時，原版最後指令
從 Poontang 的0x27回到 Theodoric 的0，亦與此寫入端一致。授權 `BeginTurn` 先重載
目前人物指令，再依既有條件算摘要，不更改 AI、正式指令、亂數或存檔。
先經 READY 審查後實作；最終程式 `ac79bb47` 以同一路徑四次455鍵通過，初次與換人
主列整圖均與未畫多餘圓環的舊基準零差。前版 `5bf08653` 僅完成遮罩呈現，尚有來源
錯誤，其收據另存保留；不混用前版與本次來源驗收。完整雜湊及限制見後述正式窄收據。

### 2. 主指令列（`已證實`）

`sub_228B7(行動者)` 清空圖示堆疊之後逐項判斷，順序就是畫面上的左到右。
第一格固定是 YES（7），最後一格固定是休息（5）。中間各格的條件見 RE-082 的表；
判斷用到的欄位是角色記錄的武器欄（+0x30，其中 +0x0C 傷害碼、+0x0D 種類）、
+0x190、0x200 起的物品欄，以及參戰者記錄的 +0x15／+0x17（手臂）、+0x19／+0x1B
（腿）、+0x1D、+0x1E。

兩隻手臂都廢（+0x15 與 +0x17 都 > 0x80）時整段武器類圖示跳過，只剩移動與休息。

腳下那一格用環 0 的第 9 項取：環 0 的位移陣列除了八個方向之外還多一項 `(0, 0)`，
所以 `sub_24E2B(0, 8)` 問的是「我站的這一格」。

### 3. 選目標格（`已證實`）

`sub_24131(mode)` 跑游標迴圈，回 0xFFFF 表示玩家取消。

```
mode 1（近戰、移動）
    起點 = 面前那一格：方向 +0x28 查 [0x0B76] 得到 3×3 格編號 n，
           列 = n ÷ 3 + 3、欄 = n % 3 + 3
    游標夾在 3…5，而且不准停在中心 (4, 4)——移到中心就再往同方向走一步
    Return：+0x28 = [0x0B6C + 3 × (列 − 3) + (欄 − 3)]

mode 2（射擊、用物品）
    起點預設 (0,0)；行動者先前 +0x25 為 0x23／0x0D 才使用上次記住的目標：
           [0x1A74 + 2i] − 自己X + 4、[0x1B36 + 2i] − 自己Y + 4
           算不出 0…8 之內就沒有可用的起點；原版在這裡也檢查了 0…8，但檢查
           唯一的效果是清掉一個馬上被覆寫的區域變數，越界的起點照樣留在游標上
    游標夾在 0…8，而且不准落在 2…6 的內圈——方向鍵移進去會把位移乘三跳到外圈
           （乘完不再夾），滑鼠點進去才還原成上一格
    Return：[0x1A74 + 2i] = 自己X + 列 − 4、[0x1B36 + 2i] = 自己Y + 欄 − 4
```

按鍵：八個方向鍵（0x4800、0x5000、0x4B00、0x4D00 與 0x4700、0x4900、0x4F00、
0x5100）移游標；`.`／`>` 與 `,`／`<` 移圖示列白框；Return 確定；白框停在
U-TURN（不是第一格）時 Return 等於取消。滑鼠（掃描碼 0xFF）落在
X 0x130…0x250、Y 8…0x98 之內也能直接指格。

游標停在有人的格上時右側資訊框換成那一名（`word_37D2A` = 精靈編號 − 1，
編號 6 時查 `[0x1C90 + 格]`）。敵人的詳細資料要智力檢定才顯示，檢定式與
RE-081 同一支 `sub_252CB`。游標離開就還原成行動者本人。

2026-09-08 訂正：此處是左側資訊框；敵方檢定只控制左下命令圖示，上方裝備／肖像與
人形／疲勞仍會畫。`0x246B4..0x246C6` 使用 **行動者** `word_2EA18` 的記錄 +0x0C
與 `word_3B264` 呼叫 `sub_252CB`，不是被檢視敵人的智力。隊員不作此檢定。
新版 dosgolem 的 `TestBattleCommandInspectionOriginal` 以槽 0、6、17 及兩種檢定結果
核對六組參數、被檢視人物及顯示閘門通過。詳見
`docs/re/20260908-command-panel.md`。已接入正式命令面板：`CommandPanel` 讀
`Round.InspectionRoll`（規劃位置進入時擲一次、取消不重擲），英文與繁中面板共用；
正常 GUI 同狀態收據待補。

`[0x0B6C]`（`07 00 01 06 08 02 05 04 03`）與 `[0x0B76]`（`01 02 05 08 07 06 03 00 04`）
互為反表，八個方向逐一往返一致，中心格對到 8。

### 4. 子選單的選項換算（`已證實`）

| 選單 | 圖示 | 攻擊選項 | 防禦選項 |
|---|---|---|---|
| 武器攻擊式（`0x1F6BA`） | 0x0F、0x2A…0x2E | `[0x0B42 + 圖號 − 0x2A]`，表 `00 01 02 05 08` | 選項 1 時直接 2；否則跑防禦式選單 |
| 徒手攻擊式（`0x1F940`） | 0x0F、0x2A、0x37…0x3A | `圖號 − 0x36`，負數夾 0 | 跑防禦式選單 |
| 移動方式（`0x1F7D9`） | 0x0F、0x3C…0x3E、0x3F、0x40、0x35 | 選中的圖號本身 | 0x3C 時 2，其餘 0 |
| 防禦方式（`sub_24AF8`） | 0x0F、0x2A、0x30…0x34、0x36 | 不動 | `圖號 − 0x2F`，負數夾 0，等於 7 時減 1 |

武器與徒手兩列都有一條收尾規則：防禦選項為 1 時攻擊選項歸零；攻擊選項與防禦
選項都是 0 時整個指令改成休息（5）。

移動方式分兩組：+0x1E 為零才有 0x3C、0x3D（+0x03 非零再加 0x3E）；+0x03 為 2
或 +0x1E 非零時，腳下磚**不是** 0x0C 或 +0x1E 非零才有 0x3F、0x40、0x35（`loc_1F87E`，
RE-148）。+0x03 在戰鬥開始時依種族設：Kelden 2、Dwarven 0、其餘 1（`sub_21D94`）；
腿廢掉清成 0，治好隊員的腿再依種族設回。種族之後接著套穿戴的魔法物品（`sub_21E0B`，
RE-154）：Flying Cloak 設 2，Speed Boots 與 Shoes 把 0 補成 1 並設 `+0x04`。

一手移動在執行段主迴圈走一格；主迴圈跑完再依同一個出手順序走第二輪（`0x20927`），
多走的格數看方式圖號（RE-154）：

| 圖號 | 說明書 | 總格數 | `+0x04` 非零 |
|---|---|---|---|
| 0x3C | WALK | 1 | 1 |
| 0x3D | RUN | 1 | 2 |
| 0x3E | SPRINT | 2 | 4 |
| 0x3F | FLY | 1 | 1 |
| 0x40 | FLY FASTER | 2 | 2 |
| 0x35 | ZOOM | 3 | 3 |

`sub_24A02` 那一列（0x2F／0x41／0x42）只在武器攻擊式且選項非 0 時插進來：
面前有符合遮罩 0x18 的人才比體型（目標 +0x0B − 自己 +0x0B），差距 < 100 多一格
0x2F；選中之後 `攻擊選項 += 圖號 − 0x40`。

### 5. 選完之後往哪走（`已證實`）

| 圖號 | 流程 |
|---|---|
| 5、0x15、0x16、0x24、0x25、0x26 | 攻擊選項與防禦選項都設 0，直接收尾 |
| 0x21 | 選目標格（mode 1）→ 武器攻擊式 → 防禦方式 |
| 0x29 | 選目標格（mode 1）→ 徒手攻擊式 → 防禦方式 |
| 0x23 | 防禦選項 0 → 選目標格（mode 2） |
| 0x27、0x3F | 選目標格（mode 1）→ 移動方式 |
| 0x28 | 指令碼改成 0x28，選項 0／2 |
| 0x0D | 背包清單 → 用法清單 → 選目標格（mode 2） |

任何一步取消都退回上一步，退到底就整個放棄這一名的規劃。

## remake 契約

- 指令列的組成、游標規則與選項換算都是規則層，可注入亂數與輸入，與繪製分離。
- 指令列本身沿用城鎮已實作的圖示堆疊（推、跑選單、白框繞回），不另做一套。
- 玩家與敵人寫同一組欄位；敵人決策已依 SPEC-008／RE-092 等後續證據接線，
  不再維持早期跳過策略。完整正常 AI 對拍仍依現行驗收清單判定。
- 原版留下的兩段死碼（`0x247E7` 清場、`0x2483F` 重畫）不實作。

## 驗證

- 主指令列的十五個條件各要一組單元測試，涵蓋「有／沒有武器」、「單臂／雙臂廢」、
  「兩腿都廢」與「+0x1E 非零」四類邊界。
- 選目標格的兩個 mode 各要驗起點、夾限與禁區：mode 1 不准停中心、mode 2 不准進
  2…6 的內圈。
- 四列子選單的選項換算逐圖號驗算，含 0x2A 落到 0 與防禦式 0x36 補回 6 兩個特例。
- 方向反表逐方向往返一致。
- 原版同狀態收據：主指令列七格已對完（RE-083）——圖示列整區 (32, 170) 216×22
  的 4,752 個像素與 frame-886 零差異，含七個圖示、六個亮藍框與第 0 格的白框。
  **基準是 frame-886 而不是 887**：白框初值在第 0 格（`sub_11722:0x1178D`），
  而 frame-887、888 已經各被 `>` 移過一格。攻擊式完整列已由後述dosgolem正常收據驗證；
  舊DOSBox-X frame-899只留輔助基準。RE-171 選目標格同相位抽驗見後段。

證據見 RE-094。三個指令碼的語意原本是從指令列的圖號推的，**三個都推錯了**：

| 指令碼 | 實際是 | 原本猜的 |
|---|---|---|
| `0x15` | 丟 | 撿 |
| `0x26` | 撿 | 地面 |
| `0x24`／`0x25`／`0x16` | 切換（手上武器與腰帶對調） | 丟與兩個未知 |

判準是各段印的訊息記錄：`0x10D drops|B|E!`、`0x111 You have found a|H…`、
`0x114 puts|B|I in|B belt`。原版 frame-887 的指令列
（`7、0x21、0x29、0x24、0x15、0x27、5`）因此讀成「YES、武器攻擊、徒手、
**切換**、**丟**、移動、休息」。

### 戰場上的物品格

十六格，物品在 `0x9D20`（一格 16 byte，第一個 byte 為 0 就是空的），座標分開放
兩張平行的表：X 在 `0x2BAE`、Y 在 `0x2D9E`。

- **丟**：找第一個空格，記下自己腳下的 X／Y，把手上那件複製進去。十六格都滿了
  就只印記錄 0x10C，這一手沒了。
- **撿**：掃十六格，X 與 Y 都要等於自己腳下那一格才算數。**撿不到隔壁格的東西**。
- **切換**：角色記錄 +0x30 起 16 byte 與 +0x190 起 16 byte 整段交換。之後腰帶那一格有東西
  印 0x114，再看手上：空的補 `!`，否則接 0x115＋0x116；腰帶那一格空的只印 0x116；最後等一鍵
  （`0x20597`…`0x20610`，RE-163）。

### 撿那一手會問（`已證實`，RE-113）

隊員（參戰者記錄 `+0x01 == 0`）撿之前先印記錄 0x111
（`You have found a|H.  Do you want to pick it up?`）停下來等 y／n
（`0x20354` 的 `sub_1B100(5)`，別的鍵重問）；敵人不問、不看手上，直接搬進怪物記錄
`+0x20` 並把 `+0x2B` 清成 0（RE-162）。

- 答否 → **繼續掃同一格上的下一件**（`0x20501` 回到同一個迴圈）。
- 答是 → 目標欄位已經有東西就印 0x112，這一手到此為止；否則搬過去，
  **撿成功本身不印任何一句**（問句已經把「找到什麼」講完了）。
- 搬完之後若 `word_32382` 還是 0 而且 `sub_2886C` 成立 → 印記錄 0x113
  （`|G, this is the quest item!  Run for the exit!`），一場只喊一次。**敵人撿到任務物品
  也會喊**，`|G` 是那隻怪物；敵人撿一般物品不印任何一句。0x112／0x113 印完各等一鍵。

**一手只撿得起一件**：搬完就跳出迴圈（`0x204E4`），同時把行動者的 `+0x25` 寫成
0x15。dosgolem 9 組接手對拍與 remake 一致（RE-162）。

問句與 0x112／0x113 三句**前面都不加動作者的名字**：問句自己就是一句完整的話，
另外兩筆的開頭本來就是 `|G`。原版對它們另起一段訊息（`sub_1C1A4`）。

### 訊息裡的名字要另外帶出來

原版是**先印訊息再搬東西**，所以 `|E`（丟掉的那件）與 `|H`（撿到的那件）展開的

帶出來，否則畫面上會是 `POONTANG DROPS HIS !`——實跑抓到的。
