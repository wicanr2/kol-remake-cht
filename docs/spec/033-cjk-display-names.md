# SPEC-033：中文畫面的資料名稱顯示

狀態：**READY**（2026-09-23，來源與呼叫點審查完成；玩家路徑尚未 CONFORMED）。
本規格只處理玩家看到的資料名稱，不改原版資料、規則比較、存檔、腳本鍵值或英文對拍畫面。

上述來源足以確認**原名的身分與使用位置**，不足以證實所有暫譯專名的文化語意；
這不妨礙先讓繁中顯示與規則資料分離。未確認的名稱不得回填原始 typed data。

## 審查後契約

1. UTF-8 TSV 是這批資料名稱的唯一譯文來源。欄位為 `key`、`en`、`zh-Hant`、
   `status`、`source`；驗證唯一鍵、欄數、編碼、重複原名一致性、來源覆蓋與中文字模。
2. 只有中文模式的**繪製端**查譯名。英文模式照原名；怪物種類、物品同一性、
   任務物品完整記錄比較、資源索引、關鍵字、保存欄位都沿用原始值。
3. 中文戰場的敵名、裝備欄、戰利品清單，以及城鎮角色資料頁、物品明細與交易
   清單接入同一來源。若某欄位含數值或控制碼，須先確認它是純顯示名稱，不能
   對整段規則字串作無條件取代。
4. 字模烘焙讀取 TSV 的 `zh-Hant` 欄，不把 `source`、`key` 或原名當成中文文字。
   新版圖像與 manifest 要在同一工具鏈重生，舊字模碼位零流失。
5. 固定同一組輸入，比較英／中兩種模式的語意狀態與保存資料；只有畫面文字與
   畫布可以不同。正常玩家路徑至少驗一場含怪物名、武器名、戰利品的戰鬥，
   以及城鎮物品頁與買賣往返。

6. **所在地（2026-09-25 補充）**：角色記錄的所在地欄是建築名前 10 個大寫字元
   （`placeKey`，RE-072），名冊右欄另接三字城鎮代碼（RE-049、RE-066）。中文名冊與刪角頁分別以這兩個
   原值查 TSV（`place.<城>.<門>`、`town-code.<城>`），組成「建築 城鎮」顯示；
   `roster.Slot.Location()`、招募比對與存檔仍用原值。同一所在地鍵在 101 棟建築中
   對到的中文名唯一，TSV 載入器對衝突譯名失敗。文字安全矩形以名冊右欄 408 px
   量「所在地＋空白＋最長城名」。

7. **教派名與頭銜（2026-09-25 補充）**：六個教派的名稱與頭銜（RE-121）列為
   `order-name.<城>.<門>`、`order-title.<城>.<門>`。入會問句、入會完成句與法術編輯
   拒絕句由 `town.Session.DisplayName` 代入譯名，中文句尾用全形「！」；角色資料頁的
   教派欄與頭銜欄在繪製端查表。`Member.Order` 與 `Sheet.Order／Title` 仍存原名。
8. **不譯的原文**：法術名由精靈語詞根組成（說明書第 7 章，如 `TYA`＝矮人、
   `KEL`＝凱爾登），玩家在法術編輯器輸入的也是這些詞，名稱本身就是法術構成規則，
   與必須輸入的原作關鍵字同類，中文模式保留原文，注解見 [SPEC-034](034-cjk-spell-name-gloss.md)。玩家自取的角色名同樣照輸入顯示。

## 呼叫點審查

- `internal/battle`、`internal/town` 與 `cmd/kol` 裡的原名仍參與任務物品完整記錄比較、
  背包／戰利品狀態、商店貨品身分及存檔；這些欄位不得翻譯。戰鬥代換碼的
  `battle.Speaker` 是即將印出的訊息快照，可只翻譯其中怪物名與裝備名；
  玩家姓名、玩家命名法術照輸入顯示。整句含控制碼或數值的不做全域字串取代。
- 明確的繪製呼叫點是城鎮交易清單／物品明細／資料頁武器、戰鬥裝備／戰利品，
  以及遭遇與勝負訊息裡的怪物名。資料頁把原名轉大寫，查表須支援這種顯示形式。
  馬廄坐騎明細與角色資料頁坐騎框已接繁中繪製，仍需正常玩家畫格驗收（#86）。
- `tools/verify_text_fit.py --display-names` 以目前欄位寬度量測 387 筆譯名在五種
  固定欄位中共 1,935 項，皆無缺字或溢出；既有其他項目加總 9,301 項失敗 0。
  實際畫格與可見截斷仍需正常玩家路徑檢查。

上述來源覆蓋只含目前已知的三份 typed data；執行期若出現未知名稱，暫時退回
原文並列入缺譯稽核，不能宣稱全部玩家文字已中文化。正常玩家路徑、英中模式
狀態差分與 GUI 畫格完成後才升 CONFORMED。此規格不涵蓋音訊、手冊譯文或
英文原版畫面差異。
