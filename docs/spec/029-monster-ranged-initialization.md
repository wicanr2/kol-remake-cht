# SPEC-029：怪物遠程能力初始化

狀態：READY（2026-09-08 完成下方接線審查）。

2026-10-04 READY增補：資格寫入後依SPEC-013同日增補重算負重與武器速度。
取用端依首byte選手持／遠程，不能保留選裝備時的舊負重。證據與限制見
[RE-216](../re/20261004-monster-ranged-use.md)。不改機率、骰序或一次性閘門。

正式契約：抽取怪物 +0x1E 為 `ranged_chance`、+0x1F 為 `ranged_code`；載入時要求
兩欄存在且為 0…255。每場由 NewQuest 建立一次待初始化狀態，首次 BeginPlanning
排順序前依敵人槽位順序各擲一次機率骰，通過才擲轉換骰；後續回合及取消重排不得重擲。
一般遭遇、任務與競技場均經 NewQuest 與首次規劃，故共用同一入口。
原版 0x1ED38 的能力初始化位於 0x1EF3F 的首次規劃前；中間屬性／等級計算不消耗此亂數。
怪物肖像維持 SPEC-019 已修的獨立 Monster.Index。未初始化敵人能力不得再填種類索引。

READY 審查依據：原始初始化區段、轉換全鏈、768＋2304 組 dosgolem 固定種子比較、
面板獨立全場索引及三種建構／規劃入口交叉核對。仍不宣稱正常整場 CONFORMED。
初始化只做一次由 `rangedPending` 保證；RE-143／145 之後 U-TURN 與逃走格答 n 走的
`Replan` 雖然每次都呼叫 `InitializeMonsterRanged`，第二次起直接返回，不重擲。

證據：[初始化寫入端](../re/20260908-monster-kind.md)。原版參戰 byte +0 不是怪物種類索引，
而是由怪物記錄 +0x1E 與 RND(100) 比較，通過後以 +0x1F 呼叫 sub_222BF 產生，未通過寫 0。
AI 射擊分支依該值是否非零判斷資格；顯示用途須另核對。

READY 條件：確認 sub_222BF 的輸入／輸出契約及亂數需求，核對資料抽取來源、呼叫順序、
原版顯示讀取端，並以 dosgolem 固定種子建立邊界案例。不能用「全部改 0」替代完整規則。

完成條件：正式 typed 資料、建構、AI、顯示及固定種子對拍貫通；正常 SLEDGE 初始值回歸，
至少一種非零案例的射擊與不符合資格案例的移動路徑通過。既有 59 欄比較保持。
## 轉換公式補證

同日已確認 `sub_222BF(code)`：擲骰次數為 `((code>>3)&7)+1`，
骰面為 `[2,3,5,7,9,11,19,99][code&7]`，總和取低 8 bit。
256 種代碼 × 三組固定種子、返回值與亂數消耗共 768 組 dosgolem 比較通過。
詳見 RE 追加證據。此公式已證實。
## 初始化機率執行補證

原版初始化區段 2304 組固定種子比較通過：先無條件擲 RND(100)，
僅當怪物記錄 +0x1E 嚴格大於骰值時執行上述轉換，否則將參戰 byte +0 覆寫為 0。
初始 sentinel 0xA5 確認失敗會覆寫而非保留舊值；最終種子相符確認消耗次數。
## 顯示用途補證

SPEC-019 同日 READY 增補已確認怪物肖像使用全場種類索引，與能力 byte 無關，
正式面板已修正並通過完整測試。
