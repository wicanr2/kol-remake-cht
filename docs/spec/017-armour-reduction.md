# SPEC-017：護甲減傷及命中後耐久

狀態：**READY**（2026-09-08）。已完成下列證據審查，授權本規格的護甲減傷與命中後耐久接線；尚未 CONFORMED。

## 目的與證據

補齊 SPEC-009 攻擊命中後、傷勢結算前的護甲與耐久處理。原始來源、SHA-256、
IDA 9.4 位址基準與訂正鏈見 [護甲控制流](../re/20260908-armour-control-flow.md)。
非破壞性定位索引為 `docs/re/armour-address-index.json`。

新版 dosgolem 的 `TestEquipmentRecordPointerOriginal` 驗證 18 個合法參戰槽；
`TestArmourReductionOriginal` 驗證兩類記錄 × 六部位 × 七組邊界，共 84 組。
後者透過明示入口橋建立區域變數，再執行原版 IDA `0x276B1` 起的後段，
保留指標、護甲與耐久原始機器碼；只替代亂數及最後扣傷子常式以核對參數。
這不是正常戰鬥或完整攻擊的動態驗收。

## 已證實規則

1. 參戰記錄 `+1` 決定兩類記錄。隊員基底為 DS 相對 `0xBB88 + index*0x300`；
   敵方為 DS 相對 `0xCD92 + (index-6)*0x80`。正式資料採隊員 0…5、敵方 6…17。
2. 命中部位順序為頭、胸、右臂、左臂、右腿、左腿。隊員使用前三個穿戴槽的
   索引 `[0,1,1,1,2,2]`；敵方為 `[0,1,2,2,2,2]`，兩者不可強行共用同一張映射。
3. 護甲碼取原始 16-byte 物品的 `+0x0C`。骰數為 `code/32+1`，骰面數沿用
   戰鬥 DS 相對 `0x00D4` 表，索引為 `(code/4)&7`。
4. 初始加值取物品 `+0x08`：大小為 `(raw&0x70)/16`，`raw&0x80` 非零時取負。
   減傷總值為此加值加每次擲骰值。不得把負減傷先夾成零。
5. 剩餘傷害為 `max(0, 輸入傷害-減傷總值)`。即使輸入傷害為零，負減傷仍可導致
   正剩餘傷害；這一組已由原版後段確認，不得額外加「輸入為零就提前返回」。
6. 全零空槽仍按 code=0、加值=0 擲一次骰，不得因沒有裝備而省略亂數或整段計算。
7. 減傷不足時，以剩餘傷害呼叫耐久處理；物品 `+0x0B` 減去
   `(物品[+0x0F]&0x20)*剩餘傷害`。結果為零保留物品，負數清空整個 16-byte 槽。
   完全阻擋則不呼叫耐久處理。相鄰裝備不變。
8. 最後將剩餘傷害、原部位、零傳給原版扣傷子常式。第三參數的完整用途未知；
   本規格不擴張它的語意。remake 的傷勢仍交由既有 `Actor.Take` 路徑結算。

## 實作前審查與接線要求

- 核對來源穿戴槽：隊員原始 `+0x100` 起十格、怪物 `+0x30` 起七格，不能拿畫面上
  六欄名稱代替完整物品。每位參戰者必須擁有獨立可變資料，不能修改名冊／怪物母表。
- 近戰 `Resolve` 與射擊 `ResolveMissile` 均在選部位後、`Take` 前套用同一規則；
  必須驗證亂數順序。不能因既有測試未提供足夠骰值而略過空槽擲骰。
- 耐久變動同步 typed `Condition` 與原始 `Record`。`Percent` 是盾牌格擋率，
  來自 `+0x0E` 低二位乘十加二十，與耐久無關，不可改動。
  破損清除物品，更新相關重量及徒手裝備快取，讓後續讀取符合空槽；不新增疲勞或其他規則副作用。
- 勝利與撤退兩路均回寫穿戴物及 `Carried`；資料頁及後續戰鬥不可復活破損物。
- 完整存檔仍依待決定的保存格式辦理。本規格不能替存檔格式作決策，也不宣稱現行 v1 能保存耐久。
- 武器傷害超上限的耐久呼叫與 `sub_21E0B` 四個磨損呼叫仍須另補證據／接線；
  完成本規格也不能把「全部耐久」標為完成。

## 驗收閘門

READY 前核對前三項資料／副作用契約。實作後，以相同裝備記錄、部位、骰序、傷害
比較原版後段與 remake；再抽測近戰、射擊、勝利／撤退回寫及正常 GUI 顯示。
保存與重載是整體交付閘門，不能由 isolated helper 或受控入口橋取代。
## 證據審查（2026-09-08）

- `extract_character_roster.py` 的 WORN_BASE=0x100、WORN_STRIDE=16 與 `extract_monsters.py`
  的前三格 +0x30／40／50，均與原版指標及槽映射測試一致。typed 物品保留完整 Record。
- `extract_town_buildings.py:good` 明確由 +0x0B 取得 Condition，Percent 則僅盾牌由
  +0x0E 計算；訂正初稿將 Percent 與耐久混用的假設，保留此訂正理由。
- 既有 IDA 資料庫 `sub_22084:0x22084..0x2211D` 無其他 CALL，只改一個耐久 byte 或
  清除整槽。既有 `ReloadGear` 契約記錄原版於動作花費與攻防讀取前重算負重；remake
  更新快取只供後續讀取，不更改正在結算的這次攻防。
- `Hurt` 原版在護甲前累加原傷害（IDA 0x2762E，RE-133）；既有 `Take` 會累加其參數。
  接入護甲時必須保留護甲前 Hurt，避免誤將受創懲罰也改成護甲後數值。直接 Take 的既有用途不改。
- 有物品而缺少有效 16-byte Record 時不得猜造耐久旗標；應明確失敗。nil 代表全零空槽，
  仍依原版擲骰。每位敵人及隊員的物品副本獨立，母表不可被磨損污染。

以上三項前置契約已核對，DRAFT 升為 READY。正常 GUI、完整保存、其餘耐久呼叫及
原版完整戰鬥仍是後續閘門，不因本次審查升為完成。
