# SPEC-026：天候圖層與正常動畫

狀態：**READY**（2026-09-08）。補充 SPEC-007；不改遊戲天候機率、日曆或紮營規則。

## 證據審查

輸入 `KOLTOWN-unpacked.EXE` SHA-256
`01f6f9a95c4adf8e9da59fa83bae57aa282e5576767b41bfc2f23302aeb9d1d2`；
IDA Pro 9.4，以下全為 IDA linear。既有 RE-136 的旋轉已經 dosgolem 驗證。
本輪 `tools/ida_probe_player_gaps.py` 從 `word_34A1A` 取址端追到初始化：

- **已證實**：`sub_2A0C6:0x2A173…0x2A185` 把底圖 0x3E0 words 複製到
  `word_34A1A + 0x117` 段，結果緩衝區初始化為完整 64×62 底圖。
- **已證實**：`sub_2A18E:0x2A1B6` 的 EGA 旋轉單位是 16 bytes，即 128 像素；
  雲層與遮罩共 155 列。PNG 的 64×62 外形只是攤平表示，邏輯雲層是 128×31。
- **已證實**：`0x2A1D9…0x2A1FB` 每個色平面只改上方 31 列、每列前 64 像素，
  下方 31 列保留底圖。合成為 `(base AND mask) OR overlay`。
- **已證實**：`sub_11390:0x11566…0x115AF` 的組 3／4 依次播放三張完整畫格，
  其餘組先旋轉雲層再合成。`TestWeatherDispatchOriginal` 六組分派通過。
- **已證實（呼叫契約）**：同支 `0x115BA…0x115C6` 在兩次更新間呼叫兩次
  `sub_1A8DF(1)`；後者以 INT 1Ah BIOS tick 等待。重製版只作 BIOS 名義頻率近似，
  不宣稱實機 wall-clock 或硬體逐週期相同。

初次 `oracle-weather/` 合成比較失敗，且測試未先把底圖複製到結果緩衝區。
此處保留勘誤：既有 runtime 的 64 像素循環模型錯誤，初次差異數也包含測試初始化錯誤，
不可把全部差異都算成產品缺陷。依本規格修正後須以相同初始化重跑。

## 實作契約

1. 正式 runtime 預載六組共 18 張既有 PNG；組切換必須改變實際資料，不能只改 Group。
2. 雲層組 0／1／2／5 使用 128 像素循環，合成上方 31 列，下方保留底圖。
3. 雨雪組 3／4 使用三張完整畫格輪播，不把第三張當遮罩。
4. 正常野外 Update 以可注入的經過時間累積動畫；每兩個名義 BIOS tick 推進一次。
   更換組別歸零相位；不前進世界日曆、RND 或隊伍狀態。不在城鎮／戰鬥背景偷偷推進。
5. 既有腳本 TICK 與雙語畫面共用同一組選擇及相位結果。
6. 驗證包含 dosgolem 合成像素、128 像素繞回、雨雪三畫格、組別切換、節拍及正常 GUI。
   完成前不升 CONFORMED；RND 不屬這個純圖層測試的輸入。
