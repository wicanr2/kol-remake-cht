# SPEC-013：射擊

狀態：**READY**（`sub_27FC1` 的飛行動畫除外）  
證據：RE-102（`sub_26D76` 的 0x23 那一條、`sub_25D7A`、`sub_25F8A`、`sub_24C35` 逐條）、
RE-104（`sub_25D0F` 與敵人 AI 的射擊分支）、RE-093／RE-105（裝填那一步與 0x22 的語意）  
授權實作：彈道、目標選擇、攻防與訊息、裝填那一手、敵人 AI 的射擊分支**是**；
飛行動畫**否**

## 1. 一支函式三種手（`已證實`）

`sub_26D76(arg_0)` 同時處理近戰、徒手與射擊。參數只決定一件事：非零才先問「面前
那一格有沒有人」（`sub_24BB6(0, 方向, 8)`），沒有就印記錄 **0x11F**／**0x120** 收工。
射擊那一條傳 0（`0x20824`），跳過這個檢查。

之後分岔的是全域 `word_31122`（目前的指令碼）：**只有 0x23 走彈道**
（`0x26EA3`），其餘走攻擊選項修正表那一段。

**0x22 與 0x23 是同一件事的兩個階段**（RE-105）：0x22 是還沒上弦、0x23 是可以射。
規劃段的分派表（`0x1FA02`）沒有列 0x22，它落 default 直接收尾，指令碼寫的是
`sub_228B7:0x22D44` 存下來的圖號；執行段 `0x20785` 把兩個一起送進 `0x20799`，
0x22 在那裡必定變成裝填。所以 `sub_26D76` 裡沒有一處比 0x22——它走不到那裡。

## 2. 先裝填（`已證實`）

`0x20799`…`0x2081D`：手上武器的種類（角色記錄 +0x3D）**不是** 6／10／11，
而且參戰者記錄 `+0x1D` 為零時，這一手變成裝填——`+0x1D = 1`、印記錄 **0x15D**
（`places a bolt in|B|E!`）、指令碼歸零，這一回合就沒了。

指令列上那兩格的出現條件（RE-083）與這個檢查完全對稱：0x22 是「種類不是那三種
而且 +0x1D 為零」、0x23 是「種類是那三種，或 +0x1D 非零」，而且推 0x23 那一格
時順手設 `+0x1D = 1`。所以玩家看到 0x22 就代表這一手只能上弦。

射完之後 `0x20860` 把 `+0x1D` 清回 0（同樣只對要裝填的那幾種）。

**敵人不必裝填**：AI 在 `0x23F23` 直接把 `+0x1D` 設成 1（RE-104）。

## 3. 彈道（`已證實`）

起點是行動者、終點是規劃段記住的那一格（`[0x1A74 + 2i]`／`[0x1B36 + 2i]`）。
`sub_25D7A(0)` 是 Bresenham：主軸每步走一格，誤差項滿了副軸才走一格，
**起點那一格不判**。

每一格由 `sub_25F8A(0, 第幾步)` 判，停下來的原因寫在 `word_30A74`：

| 值 | 意思 | 判準 |
|---|---:|---|
| 1 | 樹 | 磚塊 0x0A，扣 **0x23** 點命中值，扣完還 ≥ 0 就穿過去 |
| 3 | 牆或碎石 | `[0x1312 + (磚 & 7)]` AND `[0x10CE + (磚 ÷ 8)]` 非零 |
| 2 | 半路的人 | 那一格站著人，扣掉他**體型的一半**（`+0x0B ÷ 2`）|

牆那一段有兩條例外（只對磚塊 0x23…0x2D）：**記錄 +0x1E 非零**（騎著的人，整條線
都穿得過），或者站在 0x24／0x25 上而且是第一步。

**目標格本身站的人不算擋路**（`0x260BA`）。

命中值扣成負之後原版會跳回同一格再判（`0x2612B`），而 `sub_24C35` 沒有「已經找過」
的記憶，要靠 16 位元有號數繞回正值才出得來。remake 扣一次就停，結果與原版繞完
之後相同。

## 4. 打到誰（`已證實`）

彈道停下來之後：

1. `word_30A74` 是 1 或 3 → 印 **0x121** 接 **0x122**（`tree!`）或 **0x123**
   （`wall!`），這一手結束
2. 沒被擋 → `sub_24C35(1, 停下來那一格)` 找**敵方**，沒有再 `sub_24C35(0, 同一格)`
   找任何一名
3. 兩次都沒有 → 印 **0x124**（`fires a missle but nothing is there!`）
4. 有目標 → 印 **0x125**（`fires a missle`）或 **0x126**（`throws a boulder`），
   接 **0x127**（` at|F`）

`sub_24C35` 的旗標：bit 0 篩掉我方、bit 1 篩掉敵方、bit 2／3 篩騎乘、
bit 4 與 bit 5 是 AI 專用（RE-102 的表）。空位、自己與已退出的一律跳過。

## 5. 攻防（`已證實`）

攻擊分數是 `0x26E08`…`0x26EA0`：

```
分數 = (力量 + 攻擊 − 疲勞折算 − 累積傷害 × 10 − 挨打累計 × 20 − 負重) ÷ 10 + rand(100)
```

**沒有攻擊選項修正表**——那一段在 `0x26FC4`，射擊跳過了。彈道再從這個值扣掉沿路
的樹與人。

防禦分數換成 `目標[+0x09] ÷ 2`（快捷的一半，`0x271E3`），之後接回共用的折算
（疲勞折算、累積傷害、負重、盾牌），最後 `÷ 10 + rand(100)`。跳過去的那一段裡有
「防禦選項為 0 就直接命中」與招架次數 +1，所以**射擊不看防禦選項，也不會讓對手
多算一次招架**。

防禦分數是負的一律當 0 再比（`0x27454`）——這一條近戰也適用。

分數不夠時印 **0x13F**（`but misses completely!`），不是招架句。

半路被人接下來的那一發（`word_30A74 == 2`）另有一條：攻防**兩邊都換成
`rand(100)`**（`0x27153`），彈道算出來的命中值不算數。

## 6. 敵人 AI 的射擊（`已證實`）

環上找到目標之後（`0x23E4F`…`0x23F53`）：

```
sub_25D0F() != 0（線通不到）→ 回去在同一環找下一個
word_349B2 >= 4（環號太遠）→ 貼近打
自己的 +0x00 為零 → 貼近打
自己的 +0x15（右臂）>= 0x80 → 貼近打
否則：+0x1D = 1、目標那一格記進 [0x1A74]／[0x1B36]、指令碼 0x23、攻擊選項 0
```

`sub_25D0F` **回 0 才是通得到**，它走的是 `sub_25D7A(2)`：只看地形，不比樹也不
看人。相鄰圈的 `word_349B2` 為 0，原版與 remake 均使用 `ring < 4`；
舊「相鄰圈從 1 起算」解讀及推翻證據保留在第 7 節勘誤。

## 7. remake 的落點與差異

### 2026-09-08 環索引訂正增補（READY，同日 DRAFT 審查通過）

原版 DS 相對 0x0FC0..0x0FC6 的環長為 8、16、24、32、40、48、56；
同號對應 remake RingCells，不減一。sub_2374C:0x23C1A 明確先將 word_349B2
設零搜尋相鄰圈；0x23DDE 的 1 是後續外圈起點，不能當成鄰圈編號。
因此第六節末段「門檻少一」是錯誤解讀，應保留原版 `ring < 4`。

sub_2531C:0x25332..0x25345 使用 `rand(環長-1)-1` 選首次位置，
續查由前次位置加一並在環尾回繞，直到回到原起點；續查不重新擲骰。
TestBattleRingSearchOriginal 直接讀原版表，七環各測首末合法起點及完整回繞，
14 條遍歷通過（448 個候選與 14 次終止呼叫）。原版測試只替換候選判斷出口，
不替換環表、隨機呼叫上限、游標及終止判斷。

正式修復範圍：搜尋首次起點骰面改為格數減一；EnemyShootRing 改為 4，
即環 3 仍可射擊、環 4 改靠近。保留既有地形、右臂與怪物種類條件。
不因此宣稱整棵 AI 或正常戰鬥同狀態已完成。

READY 審查：另由 TestBattleEnemyShootRingOriginal 真實執行 0x23EBB..0x23F12，
環 1..6 × 怪物種類零／非零，共 12 組射擊／移動出口通過，確認門檻沒有索引偏移。
同時保留 first-mapping 失敗收據，說明舊規格假設如何被原版表值否定。

| 原版 | remake |
|---|---|
| `sub_25D7A` 的走線 | `sight.go` 的 `walkLine`，視線與彈道共用 |
| `sub_25D0F` | `Field.LineOfSight`，**回傳值翻正**（true 是通得到）|
| `sub_25F8A(0, …)` | `State.Shoot` 與 `MissileShot` |
| `0x271E3` 的防禦 | `Actor.MissileDefenceValue`／`MissileDefenceScore` |
| `sub_26D76` 的 0x23 分支 ＋ `0x20799` | `State.shoot`（`CmdMissile` 與 `CmdLoad` 共用）|
| `0x23F15` | `State.enemyShoot`、`EnemyShootRing` |

現存差異與已修復的歷史差異分列如下：

1. 命中值扣成負之後不回頭重判（見第 3 節）。
2. **已修復的歷史差異**：AI 在線通不到時 remake 曾換下一環，原版則在同環續查。
   舊 `findInRing` 一次只回一名，會漏掉同環其他未被遮擋的目標；現已改為同環續查。

2026-09-08 訂正：第 2 項為歷史實作差異，現依本規格第六節 READY 契約修復，
將視線檢查移入同環候選迴圈。IDA 補證確認續查不重新擲起點；
見 `docs/re/20260908-ai-ring.md`。起點骰上限亦已由本節七環直接比較核對；
不再列為待查，但不宣稱完整 AI 一致。

**驗證限制（2026-09-08 訂正）**：原版亂數可由 dosgolem 固定 seed；
remake 亦須固定測試 seed，並記錄雙方設定點與其他觀察控制。
舊「原版亂數狀態不可重建，因此只能逐條對碼」不是現行限制。
本節環索引／起點／續查已有受控原版比較，完整射擊結算與正常玩家鏈仍待驗，
因此維持 READY，不能由局部測試升為 CONFORMED。

實跑收據 `docs/verification/battle-missile/` 走完玩家射擊與敵人射擊兩側：選目標格、
敵人射中隊員、傷害那一句，以及彈道撞在樹上停下。那一次實跑抓到一個 bug——撞樹與
撞牆那兩句只有 `Records` 沒有 `Message`，推訊息的迴圈把整手跳過去了，畫面上看不到
任何東西。單元測試看得到 `Records`，看不到「畫面上有沒有出現」，這是實跑才擋得住
的那一類。
