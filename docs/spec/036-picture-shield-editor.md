# SPEC-036：圖像與盾牌編輯器

狀態：**CONFORMED**（2026-09-29，鍵盤路徑與原版同狀態逐 byte 一致；滑鼠路徑依靜態讀碼
實作，未與原版實跑比較）。實作授權與決定見「共同決定」一節。

## 範圍

書本目錄 Character Options 的 `EDIT PICTURE` 與 `EDIT SHIELD`（SPEC-005 已完成的建角範圍
不含這兩項）。兩者是同一個點陣圖編輯器，差別只在編輯的檔案。

## 證據來源

- 輸入：`KOLBOOK.EXE`，SHA-256 `2cada02856d3cf5c3bec948ef3736be6f4bd47e3abce94ddf835c1678e0e5832`。
- 工具：IDA Pro 9.4（`ida-pro-9.4-idapython:locked-v1`），位址為 IDA linear；整份反組譯由
  `tools/ida_probe_kolbook_asm_dump.py` 產生，只留本機（asm SHA-256 `4949fa1f…d3fdfc`）。
- 編輯器主體 `sub_1293E`（`0x1293E`…`0x139C0`），輸入 `sub_146CE`，四支變換
  `sub_11740`／`sub_1177B`／`sub_117AF`／`sub_117EB`，寫檔 `sub_137C0`。
- 文字：BOOKDATA 記錄 0x3A（`SAVE CHANGES@YES/NO`），`assets/original-derived-data/ui-text.json`。
- 原版畫面觀察：RE-052（紅磚底、左側大編輯區、右上預覽與目前顏色、右側 16 色、底部 8 個圖示）。

證據等級除另註明外都是 `已證實`（靜態控制流與常數，逐條核對過）。

## 1. 進入

`_main` 在兩處呼叫 `sub_1293E(n)`：`n = 0` 編輯 CHARPICS，`n = 1` 編輯 SHLDPICS。
進入前走與 DELETE CHARACTER 相同的角色清單（RE-052），選定的角色經
`[DS:0x1234 + 槽]` 取得圖片記錄編號，乘 760 得到記錄位移。這張表的完整語意是 `強推論`
（角色槽對圖片記錄的索引），尚未逐筆驗證。

## 2. 資料

- CHARPICS／SHLDPICS 各 0x2F80 bytes：16 筆、每筆 760 bytes（RE-007）。
- 一筆是 40 × 38 個像素，每個像素 4 位元（EGA 16 色索引），一列 20 byte，高 nibble 在左
  （四支變換函式的 nibble 操作與此一致）。
- 編輯時複製一份 760 bytes 的工作緩衝（`0x17C` words），原檔陣列在存檔前不動。

## 4. 輸入與兩種模式

鍵盤與滑鼠並存，都經 `sub_146CE`，最後落在同一組狀態（游標 `word_26904`／`word_26906`、
目前顏色 `word_19B54`、選中工具 `word_19B4A`）。編輯器有兩種模式，由 `word_1A36C` 分派
（主迴圈 `0x12C23`），進入時是工具列模式（`= 1`）。

| 模式 | 鍵盤 | 滑鼠左鍵 |
|---|---|---|
| 工具列與色盤（預設） | `,` `<` End 白框左移、`.` `>` PgDn 右移（0…7 繞回）；Enter 執行選中工具；四個方向鍵移動目前顏色（左右 ±1、上下 ±4，4 × 4 色盤） | 點色盤立即換色；點工具列未選中的格只移白框、點已選中的格等於 Enter |
| 畫布 | 八個方向鍵（含 Home／PgUp／End／PgDn）移動游標，兩軸各自繞回（0…39、0…37）；`D` 落筆（之後每移一格畫一點）、`U` 抬筆、`X` 或數字鍵盤 5 畫一點、`C` 吸色 | 點放大圖：游標移到那一格並畫一點，按住拖曳每換一格畫一點 |

**切換模式**：`sub_146CE` 在滑鼠命中色盤、放大圖或工具列時，以及讀到 ESC（`0x14BBE`）時，
設 `word_19290 = 1`；編輯器看到它就把模式翻到另一種（`0x12EE2` 設 0、`0x130F2` 設 1），
並重畫色盤格與工具格的選中框（`sub_13357`／`sub_14FE7`）。所以純鍵盤時 **ESC 是切換
模式的鍵**，不是離開，也不是撤銷。大小寫都認。

RE-052 連送三次 ESC 畫面逐像素沒變：`word_19292` 是 `_main` 開頭 INT 33h AX=0 的回傳，
有滑鼠驅動時非零，模式雖然切了，畫面不變（`強推論`）。沒有滑鼠驅動時，進畫布模式把色盤與
工具的白框改回色 3，游標那一格（與預覽的對應點）在原色與「原色 xor 0xF」之間閃爍。

**畫布模式每一輪**（`0x13026`…）：翻模式旗標之後，若已落筆先在目前那一格畫一點（這一條
不標記已修改），再處理按鍵：`X`／數字鍵盤 5 畫一點並**抬筆**、`U` 抬筆、`D` 落筆並畫一點、
`C` 吸色，最後才移動游標並繞回。

**滑鼠**（`sub_146CE` 參數 0x0E）：左鍵點工具列第 i 格，i 已選中回 Enter，否則換成 i 回 1；
點色盤直接換色回 1；點畫布把游標移到那一格回 `x`（與上一次滑鼠點到的格相同就不算，
`word_194F6`／`word_194F8` 跨次進出保留）。點的區域屬於另一種模式時，先把要送的鍵存進
`word_194F4`、立起模式旗標回 1，主迴圈翻完模式下一次讀鍵就拿到存著的鍵。畫布一帶
（x < 185、y < 165）按住不放會一直讀，其他地方要等放開。

## 5. 八個工具（Enter 執行）

| 格 | 效果 | 標記已修改 |
|---:|---|---|
| 0、2 | 離開（同一條路，見第 6 節） | — |
| 1 | 從原檔陣列重新載入這一筆，放棄所有修改 | 清除 |
| 3 | 用目前顏色填滿整張 | 是 |
| 4 | 每列向右移一格，最右一格繞回最左 | 是 |
| 5 | 整張向上移一列，第 0 列繞到最底 | 是 |
| 6 | 水平鏡射 | 是 |
| 7 | 垂直鏡射 | 是 |

畫點（`D`／`X`／滑鼠）也會標記已修改。0 與 2 兩格在程式裡完全相同，圖示是否不同
待原版畫格確認。

## 6. 離開與寫回

```
沒有修改 → 直接離開，不寫檔
有修改   → 印 BOOKDATA 0x3A「SAVE CHANGES / YES/NO」，只認 y／Y／n／N，其餘鍵重讀
  n → 離開，不寫檔
  y → 工作緩衝 760 bytes 搬回原檔陣列那一筆，再以 sub_137C0 寫回整個 0x2F80 bytes 的檔案
```

檔名取自 `DS:0x6BE`（CHARPICS）或 `DS:0x6C8`（SHLDPICS）。編輯器不寫 CHARDATA，也不改
其他欄位。離開之後 `_main` 跳回同一張選角清單（`loc_10B26` 呼叫 `sub_1293E` 之後設 `word_26900 = 8`、`jmp loc_10AA4`），
清單按 ESC 才回角色選項。

新角色的盾牌初值固定是 BOOKDATA 第 4 項（`sub_11820:0x1263D` 抄 760 byte）；原版名冊
16 槽的 SHLDPICS 都等於它（`tools/extract_default_shield.py` 核對）。

## 7. 與說明書的差異

說明書的參考卡是 Apple II 版（`docs/manual/chapters/11-apple-ii-reference-card.md`），寫的
是 ESC 撤銷、CTRL-E 擦除、`B` 筆刷大小、CTRL-F 切換滑鼠、CTRL-G 格線、`I／J／K／M` 移動。
PC 版程式沒有這些分支（ESC 在 PC 版是切換模式），以程式為準；說明書只證實「左邊放大圖、右邊實際圖、下方圖樣與
顏色、右上是目前顏色」這個版面。

## 證據審查（2026-09-28）

初讀由子代理逐指令整理，以下各點由主工作階段回到反組譯逐條核對後才寫入：

- 兩個呼叫點的參數與兩個檔名位址、寫回只在「有修改且答 y」時發生、寫回長度 0x2F80
  （`0x12CDA`…`0x12D91`）。
- 工具分派表 0…7 的跳躍目標與 `var_12` 的設定（`0x12E71`…`0x12EB1`）；四支變換函式的
  指令逐條讀過：`sub_11740` 每列 20 byte 以 nibble 右移並繞回、`sub_1177B` 列上移並繞回、
  `sub_117AF` 列內 byte 反序且互換 nibble、`sub_117EB` 第 i 列與第 37−i 列互換 19 次。
- 畫布界限 `0x27`／`0x25`；滑鼠三個矩形的比較常數。
- 工具列模式的按鍵（`0x12C2D`…`0x12CAA`）與 `word_1A36C` 的三處寫入。
- ESC 設 `word_19290`（`sub_146CE:0x14BBE`），推翻「編輯器純鍵盤驅動、ESC 無作用」的初讀。
- 提示文字取自 BOOKDATA 0x3A。

原版行為已足以據以實作，升 READY；實作授權待下一節決定。

## 共同決定（2026-09-29）

1. 實作這個編輯器。
2. 自訂像素存進 v2 存檔：每名角色一份 40 × 38 的 16 色索引（與原版 760 bytes 等價），
   存檔格式升版；runtime 由存檔畫出，不回寫原版檔。
3. 介面照原版鍵位與滑鼠行為，繁中模式翻譯提示文字，不另加說明或復原。
4. 盾牌：先查出原版在哪裡顯示每名角色的 SHLDPICS 並接上顯示；找到之前 EDIT SHIELD
   照做但只保存資料。

## remake 實作與驗證

- 規則：`internal/bitmapedit`（按鍵、滑鼠、四支變換、存檔問句）；畫面 `ui/bitmap_editor.go`；
  書本流程 `flow.SceneEditPick`／`SceneEditor`；取圖與寫回 `cmd/kol/bitmap_edit.go`。
- 存檔 `kol-save-v3` 的 `picture`／`shield`（SPEC-023）。
- 沒有滑鼠驅動那一條的畫法（白框改色、游標閃爍）照做，鍵盤操作才看得到游標；閃爍週期
  原版是校正過的忙等迴圈，remake 取約每 10 幀換一次相位（`hardware-spec approximation`）。
- 同狀態：`TestOriginalEditorSameKeys` 用原版 KOLBOOK 從選角清單第一名進場送同一串鍵、
  答 y 存檔，remake 的 760 byte 與原版 CHARPICS 那一槽逐 byte 相同；進場畫格除左上角 DOS
  滑鼠指標 57 個像素外逐像素相同。見 `docs/verification/bitmap-editor-20260929.md`。
