# 任務物品完整記錄比對修正

日期：2026-09-08。SPEC-014 既有 READY 的 16-byte 契約落實；不升 CONFORMED。

## 缺陷及修正

`FleeOffer` 與 `QuestItemCall` 原先只比顯示名稱，會把同名而其他欄位不同的
物品視為任務指定物。原版 `sub_2886C` 卻逐一比較完整 16 bytes，包括狀況等欄位，
遇零不終止。兩個正式入口現共用 `EqualQuestItemRecords`，使用既有 `Item.Record`；
缺少或損壞的記錄不退回名稱判斷。沒有更動保存格式。

## 原版證據

輸入 `KOLTOWN-unpacked.EXE` SHA-256：
`01f6f9a95c4adf8e9da59fa83bae57aa282e5576767b41bfc2f23302aeb9d1d2`。
工具 IDA Pro 9.4；下列為 IDA 線性位址：

- `0x28875`：非任務戰鬥直接回零。
- `0x2888D..0x288A0`：角色基址加物品偏移、逐 byte 與 `[bx-46AAh]` 比較。
  目標資料為 DS:0xB956，IDA 線性 0x39826；舊筆記的 0xB926 是位址誤算。
- `0x288B0..0x288C2`：必須走滿 16 bytes 才回 AX=1，差一 byte 即回 AX=0。

以上語意為**已證實**；既有資料庫以容器暫存副本查詢，原始名稱／位址／bytes
保持不變。兩筆審查語意加入受版控索引，已自動合併重生到本機證據。
原始及附註輸出分別保留，不覆寫舊研究的形成脈絡。

## 驗證

- dosgolem 真實呼叫整支 `sub_2886C`，沒有替代常式或亂數呼叫。
  完全相同及每個 bit 各翻轉一次，共 129 種記錄 × 兩種任務旗標，**258 組**
  直接與正式計算比較通過。記錄包含嵌入零，排除誤作字串終止的解讀。
- 原版初次測試誤把 DX:AX 當成結果，旗標零時得到殘留 DX；這是驗證器回傳型別
  錯誤。修為原版 16-bit AX 後以相同命令重跑通過，失敗日誌另留 `oracle/`。
- 現行 `quest-sites.json` 的 24 個任務均有完整、非零 16-byte 記錄；未猜補資料。
- 完整 Go 回歸及建置通過。規則入口驗同名不同記錄不提示、不提供攜物逃走；
  相同記錄不受顯示名稱影響；失敗判定不消耗一次性提示，重複成功只提示一次。
- 同批 4608 組原版戰後傷勢出口比較也通過。
