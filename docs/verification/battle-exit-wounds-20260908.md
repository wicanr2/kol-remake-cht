# 原版戰後傷勢折算與敗北回寫修正

日期：2026-09-08。SPEC-027 READY；不宣稱完整戰鬥 CONFORMED。

## 修正結果

IDA 9.4 共同出口顯示：原版把本場新增傷勢折半後加回原傷勢，並非直接保存
戰中累積值。例如原傷勢 5、戰中 24，出口為 14。位元組回繞亦須保留。
之前 `writeBattleParty` 直接寫 `Actor.Damage`，且完全排除敗北，因此會保存過多
戰後傷勢，敗北時又遺失本場的傷勢與裝備變動。

現已使用 `battle.PostBattleWounds`，在勝利、撤退及敗北的共同出口回寫；
只處理原版陣營值為零的隊員，競技場觀眾不被改動。已發生的護甲破損／耐久、
手持、腰帶與背包修改依既有契約保留，沒有猜補額外掉落或扣錢。

- IDA 原始位址、輸入身分及 READY 審查見 [SPEC-027](../spec/027-battle-exit-wounds.md)。
  探針使用唯讀原資料庫的容器暫存副本，沒有改名。三筆經審查語意由受版控索引
  自動併入新的證據匯出，原始未註記輸出仍保留。
- dosgolem `fd746405cf0ef9e535121e215b935b0bf59cd1de` 真實執行共同出口，
  六個舊傷勢邊界 × 256 個戰中值 × 三種陣營，共 **4608 組**通過。
  審查後再直接比較正式 `PostBattleWounds`，4608 組仍通過。
- 測試只替代角色取址，入口橋建立原函式堆疊；六槽迴圈、陣營門檻、
  算術及 byte 寫回均執行原版指令。此段沒有 RND 呼叫。
- 完整 Go 回歸及建置通過。固定 remake seed=1 的保存整合擴充為五條：
  一般勝利／撤退／敗北與競技場勝敗，經正式結算、v2 寫入及重載，逐欄比較角色。
  檢查原傷勢 5→戰中 24→保存 14、護甲破損、未受損配件、一次性獎勵／升階／賭金、
  非連續名冊槽位與發言者。這是受控結算狀態，不是正常 GUI 戰鬥。

舊 [三條保存鏈測試](battle-save-chain-20260908.md) 只證明當時轉接資料能往返，
未證明 `Damage` 全額保存符合原版；本次直接原版證據推翻該預期，舊收據保留。
