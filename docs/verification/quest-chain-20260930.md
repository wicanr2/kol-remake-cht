# 任務鏈：接任務、撿物、帶物逃走、交付、住宿存檔與重載（2026-09-30）

## 結果

remake 的正常玩家路徑從標題一路走完一條任務鏈：接下 Ship Wheel 任務（地點 6）→ 戰場上撿起
Ship Wheel → 帶著走到戰場邊答應逃走（全隊任務旗標成為「完成」）→ 回 7 號門交付（換成
Treasure Map，全隊旗標成為「回報過」、已回報數各加一）→ 旅店住宿寫出存檔 → 讀檔重載後
同樣的旗標、已回報數與物品都還在。

原版那一側用「關鍵點接手」：把狀態直接寫進原版記憶體，從任務鏈四個關鍵點的常式呼叫，比寫回
的欄位與 remake 同一條規則的結果（RE-162）。四個關鍵點全數一致；比的是機制，不是畫面，也
不要求整條路徑的回合數或勝負與原版相同（2026-09-29 使用者決定）。

```
tools/replay_player_path.py quest-chain quest-chain-reload   # remake 玩家路徑
# 原版關鍵點（容器內，/src 與 /repo 唯讀）：
KOL_CHECK=quest bash /src/tools/oracle/check_updated_dosgolem.sh
```

## 受控條件

- 種子 1，從標題起跑；野外遭遇擲點前 200 次以 `-ambush-rolls` 固定為 100，路上不遭遇。
  戰場內一律種子亂數，沒有受控骰。
- 戰鬥按鍵由 `tools/drive_battle_script.py`（`KOL_DRIVE_QUEST=1`）依軌跡打出：離任務物品最近的
  隊員走去撿、撿到後找最短路走到戰場邊；其餘隊員身邊有敵人就打，否則跟著持物者。這是玩家
  策略，不改規則；戰場地形由軌跡的 `walls` 欄位提供給驅動器找路。

## 不宣稱

- 原版沒有跑同一條完整路徑；四個關鍵點之間的銜接（戰鬥外的城鎮對話、野外步行、住宿）由既有
  收據與規格各自驗證。
- 接任務那一步（MOUTH 關鍵字）沒有原版接手比較，沿用 SPEC-014 第 1 節的旗標位置與既有收據。
- 敵人在正常戰鬥裡自己走去撿任務物品的 remake 收據尚未取得；規則層與原版接手一致。
- 住宿的回復量與扣款依 SPEC-006，不在本次比較範圍。
