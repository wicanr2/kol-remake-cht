## 已確認的操作原則

使用者本輪明確決定：**滑鼠可取代鍵盤，只要操作結果等價於原版即可**。
因此不把鍵位不同、滑鼠轉成一串鍵盤指令或新增點選入口本身列為不忠實；驗的是
選中的角色／目標、資源增減、規則結果與保存狀態。這不等於要求所有流程只能用滑鼠，
也不授權省略原版行為。前輪地圖點擊的裝置差異不能單獨作為否決重製版的理由。

## 優先處理的實作缺口

### A01：正式建角流程未完成（阻塞）

依據：SPEC-005；`internal/flow/flow.go:129`、`:148`，
`internal/charcreate/charcreate.go:161`、`:199`，`cmd/kol/main.go:1324`、`:1644`。

- 從角色選項選「建立」時，先呼叫新建狀態的 `Cancel()`，使名字層變成
  `StageAbandoned`。再輸入 A，名字仍是空字串；測試重現 `Stage=7`。
- 正式 `flow` 繪製建角時走 `sceneNewChar`，該分支只畫背景與固定肖像；真正讀
  建角狀態的表單在 `sceneScript`／`sceneScriptCJK`。
- `flow.newchar` 的 Escape 直接退角色選單，沒有依規格逐層返回；測試重現種族層
  Escape 後仍是種族狀態、外層畫面卻已回選單。
- 接受圖像只將狀態設為 `StageDone`，正式入口沒有接名冊新增、容量檢查、原子保存
  與返回選單。原版 CHARDATA 寫入對拍工具不是 remake 的正式角色保存功能。

完成條件：正常啟動 → 建角 → 接受圖像 → 名冊出現 → 可選入隊 → 離開重啟後仍存在，
並驗取消、滿槽與寫入失敗。穩定角色 ID、Unicode 名字與 schema 的矛盾須先回規格處理。

### A02：選角只換畫面，沒有更換實際隊伍（阻塞）

依據：SPEC-005 的角色儲存區；`internal/flow/flow.go:191`，
`cmd/kol/main.go:2935`、`:3000`、`:3576`。

`SelectCursor` 用於顯示清單，Return 只把 Scene 換成旅店。城鎮隊伍早已由戶外樣本
或 `-load` 建好，沒有把選中的 slot 轉成隊伍。測試選第二名 SECOND 後，實際隊伍仍是
Theodoric。名冊刪除也只改記憶體，沒有持久保存或同步已建立的城鎮候選清單。

完成條件：選不同角色後，旅店、城鎮、戰鬥與存檔中的名字、屬性、裝備一致；
刪除與重載也必須作用於同一份角色儲存區。

### A03：戰後沒有完整回寫角色與物品（阻塞）

依據：SPEC-008／010／014；RE-094／096／109；
`cmd/kol/main.go:101`、`:543`、`:1911`；`internal/battle/items.go:74`、
`internal/battle/spoils.go:124`。

城鎮角色被轉成獨立的 `battle.Member` 與 Actor。出口會發金冠／冒險點數，
但沒有完整把 Actor 傷勢、手持物、背包戰利品等還原到 `town.Member` 就丟掉戰鬥狀態。
最小出口測試設傷勢 23 與一件戰利品，退出後仍是傷勢 0、空背包。

任務旗標共用 slice，**這條有接**；但戰鬥撿物只保存名字與武器數值，交任務端比對
的是 `Carried` 的十六個原始 byte。兩套物品表示沒有同步，不能用旗標已完成證明
「拾取任務物品 → 回城交付」已完成。打輸後兩邊一律回野外，原版敗北後處置仍未知。

完成條件：同一角色受傷、丟武器、撿物、領戰利品後離開戰鬥，城鎮與保存資料都保留
結果；至少抽測普通戰鬥與任務戰鬥。敗北規則另回 RE／spec，不能猜補。

### A04：存檔遺漏可變狀態，設定也未完整套回（阻塞）

依據：SPEC-006；RE-075／076／127；
`cmd/kol/main.go:604`、`:790`、`:3019`、`:3175`，`internal/save/save.go:113`。

- `buildSave` 沒保存 `Backpack`、`Worn`、`InHand`、訓練後的武器技能與 Nutrition。
  測試放入新裝備、技能 777、Nutrition 37，序列化後均無對應資料。
- 讀回時 Sheet 與裝備取自原始名冊；訓練消耗的冒險點數會保存，練到的技能卻不會。
  任務用 `Carried` 並不能補救，因為購物與穿戴動作沒有同步它。
- 讀回金冠 0 會被當作缺值，補成原始名冊的錢；這與「0 是合法存檔值」不一致。
- `save.Settings` 的單元往返會保留未知鍵，但正式 `buildSave` 每次 `save.New()`，
  未帶回 `Extra`；載入的 `faithful_inn_stay` 也未套回，實際使用命令列旗標。
- 世界日期、時間與 RNG 狀態未保存。SPEC-006 還寫「世界時間尚無規格」，但已有
  SPEC-007；2026-09-03 的使用者決策又明列存世界時間。這是**規格本身也需補齊**的缺口。

完成條件：購物／換裝／訓練 → 住宿 → 重啟讀回，各可變欄位一致；加入零金冠、
未知設定、空裝備與不同日期樣本。格式擴充須先修訂規格，不在測試裡自行定新格式。
