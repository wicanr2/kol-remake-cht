本輪將重製版驗證從逐回合接手，推進到標題選角、招募、自然遭遇、連續 61 回合及
返回世界。兩側在首次規劃入口固定相同測試種子後，61 個執行入口、60 次新規劃的
持久戰鬥狀態與 1458 次骰序通過。正式程式未改；控制種子與完整觀察只在研究副本。
正常原版出口另證實搜刮兩件物品與一人金幣，現行產品缺少此段，不宣稱完整戰後鏈完成。

## 連續戰鬥的比較邊界

現行正式程式直接使用 `-seed 1` 從標題走正常路徑，初核在 58 回合敗北。
它在排首次規劃之前播種，原版收據在首次規劃等待入口重設種子，因此測試條件不同，
不能直接把回合數差異當規則缺陷。研究副本在同一首次規劃時點原地重設共用 LCG，
初始隊伍順序保留，不重排、不換掉規劃端已保存的亂數參照。

英中各 501 筆正常操作狀態、501 張畫格，包含標題、自然遭遇、全部戰鬥與返回世界。
兩側 61 個 `IDA linear 0x1FD21` 執行入口的種子、三名有效參戰者位置、六部位、
累積傷勢、方向、招架、挨傷、指令、攻擊式、防禦式、相關旗標與疲勞／體力完全相同。
60 次新規劃比較回合完成後的部位、傷勢、位置與計數器；第一次規劃等待的種子亦相同。
1458 個 `rand(n)` 的 n 與每次入口種子全部一致；第 61 回合敗北及戰後傷勢 24／19 一致。
英文與繁中觀察中的參戰者、隊員、種子及骰序全部相同。
終態原版把Theodoric／SLEDGE指令清為0，重製暫存仍為41／33；其餘已列欄位與計數器
相同。指令暫存於返回世界時棄置，不把它算成原始記錄全欄位一致；正式收據明列此差異。

原版一次移動會印中途訊息，重製有合併訊息的步驟，故逐鍵中間畫格不是相同比較點。
本收據按規則邊界與播種契約比較，不把微狀態差異忽略後宣稱畫面完全一致。
原版世界位置為 `(49,23)`，重製為 `(51,23)`，世界完整同狀態未證實。
原版最後一次戰後 Return 已送入但尚未執行，不把它記成消耗完成。

首版研究觀察器換掉亂數物件後，規劃仍讀舊參照，且參戰者 slice 未複製，導致早期
快照被後續狀態覆蓋。gui3／probe1保留作診斷，不能作產品缺陷或同狀態驗收證據。
probe2修正共用參照與逐步複製，明確檢查首次傷勢 0、終態 48，防止再次把終態當初態。

## 正常原版的出口回寫（已證實範圍）

原版從 `IDA linear 0x211AD` 繼續到八次真實 `sub_1B100` 等待。
第一張為 record378 敗北圖；下一張 record225 已返回世界，角色傷勢從 0／0 回寫為
24／19，對應戰中累積傷勢 48／39，符合既有 [SPEC-027](../spec/027-battle-exit-wounds.md)。

IDA Pro 9.4 暫存資料庫窄查保留原始函式名、位址、運算元、bytes、xref與已審查索引。
七筆新[分級語意](battle-settlement-address-index.json)由同一匯出工具自動合併，
原始定位不改，未附加已證實語意的指令仍帶警示。
位址採 `IDA linear`，執行時原始記錄採 DGROUP 相對位移；兩種空間分別標示。
原始出口 `0x21776..0x21869` 走訪隊員，倒地者從角色 `+0xA0` 至 `+0x190` 每 16 bytes
擲 `rand(100)`，跳過 `+0x170`。結果嚴格小於門檻且未受任務物品保護時清空該槽；
即使槽已空仍擲骰。接著另擲一次決定是否清空 24-bit 錢包，最後才進共同傷勢回寫。

本例保護開關 DGROUP `+0x6A98` 為 0。門檻讀自 `+0xCDAD`；其前 32 bytes 與
固定封裝 TOWN0 payload32（怪物索引27 SLEDGE）相同，對應怪物記錄 `+0x1B=20`。
不宣稱更長記錄或所有怪物執行期資料原樣不變。

32 次搜刮骰的前後種子與兩名倒地者的 15 個物品槽＋錢包順序相符：Olear `+0xC0`
擲 11、Theodoric `+0xC0` 擲 19，均清空；Theodoric 錢包擲 8，1009 金冠清零。
Olear 手上武器在戰中已失去，出口不恢復。獨立來源模型重建六個完整 768-byte 角色
記錄全零差，省略搜刮的反例被拒絕；來源模型通過不等於產品已有搜刮。

`post2` 的歷史觀察鍵名 `arena_word_cd8a` 只是原始 word 的標籤；此位址是重用暫存，
在不同階段為 2267／2 等值，不是固定競技場旗標。未證實門檻以外的初始化與分支
控制資料流前，不可直接依此鍵名實作競技場、勝利／撤退或任務保護。
