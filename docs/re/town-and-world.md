# 城鎮與世界

七座城與一張荒野地圖的所有資料都在 `TOWNn.0` 這八個檔案裡——磚圖、地圖格子、門的
座標、建築的文字與商品、關鍵字表、世界地圖、遭遇機率，甚至戰場的地形。這份把
payload 版面整理在一起，因為**同一個 payload 在不同城鎮扮演不同角色**，弄混了會
一路錯下去。

`TOWNn.0` 之前不在資產清冊裡，因為清冊工具只認名字含 `PIC` 的檔案（RE-057）。

## TOWNn.0 的 payload 版面

| payload | 內容 | RE |
|---|---|---|
| 0／1／2 | 磚圖各 96 塊，16×16、四個 EGA 平面、plane-major，一塊 128 byte。解碼後首尾相接成 36,864 byte，載到同一 segment 的 `0x0000`／`0x3000`／`0x6000` | RE-057、058 |
| 3 | 地圖與門的總表，見下 | RE-059、061、065、068 |
| 4 | **只有 TOWN0 用**：野外遭遇的機率與遮罩表 | RE-078 |
| 5…36 | **只有 TOWN0 用**：32 隻怪物，一筆 512 byte，第 0 byte 是名稱長度 | RE-078 |
| `i + 4` | 第 i 個門（建築）的文字 | RE-061 |
| 20 | 話題關鍵字與人名表 | RE-067 |
| `0x3D + i` | **只有 TOWN0 用**：任務戰場的格子，RLE 解開再轉置成 64×64 | RE-080 |

### payload 3 的位移

城鎮與野外共用同一份結構，但兩邊載到不同基底（城鎮 `sub_10000:0x106AB` → DGROUP
`0x4430`；野外 `sub_29004` → `byte_2FBC4`，DGROUP `0x1CF4`），所以**同一個位移在
兩邊指的是不同東西**——這是最容易搞錯的地方。

| 位移 | 內容 |
|---|---|
| `0x00`…`0x1F` | 磚塊編號的不可通行位元圖（城鎮） |
| `0x20` | 門數（迴圈是 `<=`，實際讀到門數 ＋ 1 筆） |
| `0x27 + 2k` | 第 k 個城門在**世界地圖**上的 X／Y（TOWN7 有 10 個，其餘 1 個） |
| `0x47 + 2i` | 第 i 個門在城鎮地圖上的 X／Y |
| `0x100 + 磚塊` | 地形碼（取最低位的 1） |
| `0x200 + 磚塊` | 野外的逐磚塊屬性 |
| `0x300` 起 32 byte | 野外的不可通行位元圖 |
| `0x320`／`0x321` | 競技場與賭場那一格 (55, 13) |
| `0x323`／`0x33B` | 24 個任務地點的 X／Y |

地圖格子陣列本身不在 payload 3，而是在磚圖 segment 的前 4 KB：段內
`0x0000`–`0x0FFF` 是 64×64 的格子陣列（一格一 byte），`0x1000`–`0x8FFF` 是 256 塊磚
（RE-059）。格子索引是 `(X << 6) + Y`。

### 建築的 payload 內位移

第 i 個門的文字在 payload `i + 4`，那一份 payload 裡：

| 位移 | 內容 | RE |
|---|---|---|
| 128 起，每 16 byte 一格 | 5-bit 打包的文字，一則訊息 4 格 | RE-062 |
| `0x17`…`0x1C` | 六個話題槽 | RE-067 |
| `0x38`／`0x39` | 住宿價錢（16-bit）／修道院的每點傷勢單價 | RE-073 |
| `0x50` 起，一筆 0x0C byte | 四門技能（掃到 `0x80` 為止） | RE-076 |
| `0x100` 起，一筆 16 byte | 商品表（最多 32 筆，第一個 byte 是 0 就結束） | RE-075 |

## 城鎮

**地圖是捲動的磚塊圖**，視窗 12×6 格、每格 16×16，移動時以 16 px 為單位捲動
（RE-056）。隊伍標記是 KOLPICS payload 0 的十個 128-byte 精靈，外框是把四平面 OR
成佔用位圖後左右膨脹一像素再反相算出來的——膨脹在 little-endian word 上做，因此
不跨位元組邊界（RE-060）。

**夾限的是鏡頭不是隊伍。**走到地圖邊界時鏡頭夾住，跳出 DOOR／U-TURN 提示、地圖
視窗換成 MISCPICS 圖 0 的林地圖（RE-065）。

**門口是狀態不是位置。**掃門迴圈接在移動後面，所以剛從建築物走出來時隊伍就站在門的
座標上，畫面仍然是地圖（RE-061）。

**圖示列有生命週期**：走離門口清空、踩到門重建成兩格、選 U-TURN 或從建築物出來都
只剩一格 DOOR。

### 建築內

進門敘述是訊息 0 與 1 合起來的八行。畫面規則只有兩條：句號後兩個空白且下一個字母
大寫、逗號後一個空白（RE-062）。

對話走六個話題槽：**LISTEN** 講沒有掛關鍵字的槽，**MOUTH** 用四字元字首比對關鍵字表
（payload 20，七座城共 305 個，按字典序排好）。招呼語依性別、會不會法術與聲望等第選
（RE-067）。payload 20 的版面：

| 位移 | 內容 |
|---|---|
| `0x000 + 4i` | 64 筆關鍵字：三個 byte 的字串 ＋ 一個碼 byte |
| `0x100 + 8i` | 16 個人名 |
| `0x1C0 + 話題碼` | 這個話題該去問誰（`0xFF` ＝ 沒有人知道） |

## 世界

**世界地圖的城鎮記錄**給出七座城的位置、界限、三字母代碼與磁碟編號（RE-066）。
城名由代碼配上城鎮對話的一手證據定出來：`BRT` 布雷特爾、`HTN` 赫特隆、
`THM` 辛博瓦德、`POT` 波伊特水閘、`SHL` 謝勒農、`OLN` 奧蘭斯、`MIN` 霍布（礦坑）。

**城門與世界地圖用同一組座標**——payload 3 的 `0x27 + 2k` 那一欄與世界地圖城鎮記錄的
座標 16 組全部相同（RE-069）。

**移動有次格座標**：`word_2DF36`／`word_2DF38` 在 0…7 之間繞回，繞回時世界座標才走。
隊伍標記畫在視窗第 3 列第 5 欄那一格內，偏移「次格座標 × 2」像素（RE-068）。

**道路是方向遮罩**，ROAD 與 SIGNPOST 是同一支自動循路，只差方向（RE-071）。
循路一步扣 20 個時刻。

**時刻、日曆與天候**見 RE-077；**隨機遭遇**（什麼時候擲、機率表、怎麼挑怪、數量與
等級、能不能騎走）見 RE-078。
