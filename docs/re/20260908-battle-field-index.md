# 戰場亂數位置的索引差異

日期：2026-09-08。輸入 `KOLTOWN-unpacked.EXE`，SHA-256
`01f6f9a95c4adf8e9da59fa83bae57aa282e5576767b41bfc2f23302aeb9d1d2`。
IDA Pro 9.4，以下 `0x1E...` 均為 IDA 線性位址；執行期 DGROUP 相對位移另列。
使用既有 `.i64` 匯出 `workplace/monster-panel-20260908/monster-kind-private.json` 的
`initial` 指令及 RE-080 的繪製／固定地圖載入資料流，不改原始名稱或位址。

## 已證實的資料流

- `0x1E5B0..0x1E5BE`／`0x1E5C5..0x1E5D3`：從 `word_30A6A`／`word_30A6C`
  讀取遠指標，依序寫入原版 4096 格；執行期指標在 DS:2B9A／DS:2B9C。
- `0x1E618..0x1E627`：`sub_1B5A8(4096)-1` 產生原版線性索引。
- `0x1E66A..0x1E679`：遠指標加同一索引後寫入樹叢 0x0A。
- RE-080、`sub_223C0:0x2250C..0x2253B`：原版視窗按 `Y*64+X` 取格；
  `sub_2B3D1:0x2B436` 對固定地圖轉置。正式 `Field.At` 則按 `X*64+Y` 取格。

原版線性索引 `n` 對應重製版索引 `(n%64)*64+n/64`。這是表示方式轉換，
不改原版座標、骰面、骰序、地形機率或固定地圖內容。

## 修正前 dosgolem 證據

`TestBattleFieldGenerationOriginal` 實際執行原版 `0x1E58A..0x1E68B`，
僅建立區域變數堆疊並在站位初始化前返回；保留真實 `sub_1B5A8`。
三組共同固定種子 0、1、65535，各比較一般生成與固定測試地圖灑點的全部 4096 格。
固定測試地圖包含草地、粗地、道路與牆，且非轉置對稱。

| 種子 | 一般生成差異格 | 固定地圖灑點差異格 |
|---|---:|---:|
| 0 | 1894 | 326 |
| 1 | 1856 | 318 |
| 65535 | 1870 | 349 |

每組亂數終態相同，排除本次比較中的亂數消耗差異。來源、工具版本與測試來源雜湊
見 `workplace/terrain-oracle-before-20260908/manifest.json`；結果見 `terrain.log`。
此結果推翻 SPEC-008 早期「亂數來源不同，因此排除樹叢對拍」的限制，保留歷史收據。
這是原版區段對拍，不是完整正常戰鬥 GUI 驗收。

## 正常畫面匯出指標勘誤

正常入口第一次匯出讀 DS:2B9A／2B9C 得到非地形資料，檢查拒絕產生地形收據。
該指標只在生成／灑點區段有效，不能當作跨階段穩定指標。
IDA Pro 9.4 重新從同一 `.i64` 匯出 `sub_223C0` 與 `sub_2B3D1`，證實
`0x2254E`（bytes `8e06ba2d`）直接 `mov es,word_30C8A`，
`0x22552`／`0x22555` 以 SI=Y*64+X 取 `es:[si]`。
因此正常規劃畫面的地形段應讀 **DS:2DBA**，段內基底為零（已證實）。
`sub_2B3D1:0x2B409` 也從同一欄位取得固定地圖輸出段，與生成入口
`0x1E57E` 複製至暫存指標的資料流一致。

原始指令、bytes、函式界線及索引附註保存在
`workplace/field-pointer-20260908/field-pointer-private.json`；原始名稱不改。
失敗收據保留在 `workplace/battle-terrain-normal-20260908/`，不改寫歷史。
