# 戰鬥

戰鬥是原版最大的一塊，也是玩家評價最兩極的一塊。這份是**導覽**：每個階段由哪一支
負責、證據在哪一條 RE、哪些已經解出來、哪些還沒。行為契約在
[SPEC-008](../spec/008-combat-field.md)、[009](../spec/009-combat-attack.md)、
[010](../spec/010-combat-commands.md)，數字與逐條反組譯在 RESEARCH-LOG。

## 一場戰鬥的形狀

```
進入            → 任務地點（sub_2B0FF）或野外遭遇（sub_2A4E5）
遭遇畫面        → 滿版怪物圖 ＋ 記錄 0xE9／0xE7
戰場            → 9×9 視窗、視線、參戰者
  ┌ 規劃段 ────────────────────────────┐
  │ 每個參戰者依序決定這一回合要做什麼      │
  │ 隊員：指令列 → 目標 → 子選單           │
  │ 敵人：sub_2374C 決定                  │
  └───────────────────────────────────┘
  ┌ 執行段 ────────────────────────────┐
  │ 依「快捷值」排序，一手一手做出來        │
  │ 每一手印一句訊息，等玩家按一次鍵        │
  └───────────────────────────────────┘
                → 隊伍全倒就結束；打贏那一邊還沒解
```

## 幾個容易踩的地方

**一回合分兩段，不是一人走完一輪。**規劃段先讓每個參戰者各自決定，執行段才依快捷值
重排順序做出來。所以決定的順序與執行的順序不同（RE-080）。

**移動一次只走一格，沒有點數規則。**先前把「移動方式」（步行／奔跑／衝刺）誤讀成
距離，RE-085 推翻了那個假設。

**兩處子選單容易標反。**`0x1F6BA`（0x2A…0x2E）是**武器**攻擊式、`0x1F940`
（0x37…0x3A）是**徒手**。三個判準：分派表、`[0x0FD2]` 只有六筆、`[0x110A]` 的九列。

**一場戰鬥的敵人只有一種。**`sub_2687F` 印敵人名字時**不帶索引**，固定讀
DGROUP+0xB967 那一份，所以同一場所有敵人共用一個名字（RE-090）。

**移動成功要按兩次鍵。**原版是「印訊息 → 等鍵 → 重畫戰場 → 再等鍵」，同一句會出現在
兩張連續畫格上（RE-085、089）。

**訊息整段轉成大寫，白底黑字，底圖是 MISCPICS 圖 1 的卷軸。**執行段一開始就把
(8,164) 起 296×32 那一整條換掉，指令圖示列被蓋住（RE-089、090）。

## 還沒解的

- **打贏的判定與收尾。**目前只知道隊伍全倒會結束。入口已經定位——`sub_289EE`
  （467 條指令，戰利品與升級），但還沒解讀。KOLDATA 記錄 372…384 是那一段的訊息
  （`You have defeated|F`、`receives|N adventure points, and`、`|N gold crowns!`、
  `you have gained a level!`），可以拿來對照。
- **敵人那一手的執行期值。**決策樹解出來了，但 `byte_3496A`／`3496B`／`3496C`、
  `[0x6AD2]`、`[0x1A9A]` 三張基礎權重表要在執行期取樣才知道內容。
- **撿、丟、背包三手**（指令碼 0x28／0x29／0x2A）。
- **擊退與昏迷**（`0x27B77` 之後，訊息 0x158…0x15C）。
- **法術。**戰鬥指令列有 MAGIC，訊息鏈也有 `casts|S at|F.`，但整個法術系統沒碰過。
- **經驗值與戰利品。**見上面的「打贏的判定」。
