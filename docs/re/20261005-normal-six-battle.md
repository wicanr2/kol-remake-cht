# RE-238：原版正常六人隊伍的首場戰鬥

本輪先補正常入口證據。沿用 RE-232 的 40 鍵招募六人，再正常離店、出城與旅行。
只在旅店招呼後設定一次 seed 1，不注入人物、座標、遭遇、指令或勝利，不替換等待常式。
既有 AI 局部常式與重製版任務鏈驗證保持；本輪不以新增觀察取代同狀態驗收。

## 預先登記的驗證範圍

- 固定原版工具 revision `968ca774705853276ae55c8d1163c369481ac71f`。
- 核對現行 338 項程式輸入，正式 Linux SHA-256 為
  `38f86f38b1531c37f436e357aca251e83e5c85ff1236992dbc5e5add2337db16`。
- 正常招募六人、離店與出城。旅行採既有任務方向前綴，遇到第一場自然戰鬥即停旅行。
- 最多觀察兩回合、120 個戰鬥操作鍵。記錄原始人物、18 槽參戰資料、耐力、疲勞、
  地形、亂數呼叫參數及原始呼叫位址。
- 兩侧相同 seed 數字不證明全程骰序相同。未比較同狀態前，AI GUI 工作保持未完成。

## 輸入與入口

本機工作區為 `workplace/normal-six-battle-20261005/`。入口 `prepare.py` 固定方案與輸入雜湊，
`build.sh` 重建原版工具，`probe.go` 只送正常按鍵及唯讀觀察。
原版檔案唯讀，存檔寫入獨立 `scratch/`，含原始資料的收據只留本機。
位址分別使用執行期 DGROUP 相對位移與 IDA 線性位址，換算基底為
`DGROUP segment*16 - 0x2DED0`。

本輪實際載入 `KOLTOWN.EXE`，SHA-256 為
`c2442c8438ce8812926d61555626f67f918a5c9ed9c42939d98938535fddb221`。
既有位址索引對應 `KOLTOWN-unpacked.EXE`，SHA-256 為
`01f6f9a95c4adf8e9da59fa83bae57aa282e5576767b41bfc2f23302aeb9d1d2`。
全部 75 個原版輸入與大小保存於工作區 `original-inputs.json`，執行前後核對不變。

| 觀察資料 | 原始定位與位址空間 |
|---|---|
| 六名人物原始記錄 | DGROUP `0xBB88`，步幅 `0x300` |
| 18 個參戰槽 | DGROUP `0x6712`，步幅 50；只解讀有效上界內的槽 |
| 耐力與疲勞 | DGROUP `0x1C50`／`0x322E`，每槽一個 word |
| 地形 | DGROUP `0x2DBA` 的段指標，段內 `Y*64+X`，共 4096 byte |
| AI 入口與加權輪盤 | IDA linear `0x2374C`／`0x25A3A` |
| 執行與回合規劃入口 | IDA linear `0x1FD21`／`0x1EF3A` |
| 亂數與種子 | IDA linear `0x1B5A8`；DGROUP `0x1600`／`0x1602` |

定位沿用 [戰場索引證據](20260908-battle-field-index.md)與
[RE-237](20261005-ai-move-globals.md)，本輪只增加正常入口觀察，不重解未知 byte。

## 結果與證據等級

已證實原版正常招募六人、出城及自然遭遇三名 1 級懸崖巨魔。修正輸入腳本後共
247 個狀態、兩次回合結算、七次 AI 入口及 4710 次亂數呼叫觀察。種子只在旅店設定一次。
前 41 個招募狀態的人物資料與 PNG 全部符合 RE-232。兩次原版執行前 215 狀態完全相同。

正式 38f86f38 從標題重播等效按鍵，沒有遭遇覆寫。雙語各 173 狀態，只有第 171 步
遭遇文字不同。114 個世界位置及時刻比較點全符。九名有效參戰者的位置、頭與胸 HP、
目前 Olear 規劃、第一回合、圖示列及選取值符合原版。
320×200 畫布的戰場區域 `(152,8,144,144)` 像素差為 0。姓名大小寫及其他區域另有差異。
[未裁切比較頁](../../workplace/normal-six-battle-20261005/review.html)可查看三張原圖。

原版地形為 4096 格，值為 9、10、13。本輪只逐像素比較可見戰場，未核整份重製地形。
全部 50-byte 記錄、後續 AI、存檔、完整任務及平台驗收不由本輪升格。338 項正式輸入不變。
下一步沿本輪正常起點比較兩回合決策與結算，再核仍未完成的 AI 分支。

## 工具失敗與等效輸入

首次原版觀察到達正確戰鬥，腳本卻在「開始下一回合？」送 Y，120 鍵上限內沒有結算。
完整 290 狀態、176 張 PNG 及日誌保留在 `original/`，不能把 Go PASS 當成兩回合驗收。
`probe-corrected.go` 改用 YES 圖示及 ENTER，執行訊息以 SPACE 推進，沒有等待 stub。
正常重跑保留相同輸入、seed、版本及資源；兩回合來源在 `corrected-original/`。

原版換日後多送的第 152 鍵 SPACE 不改任何已觀察狀態，正式野外腳本拒絕它。
兩次拒絕的輸出保存在 `remake-en/` 與 `preaccept-en/`。等效按鍵僅省略這一鍵，
省略理由與兩側索引在 `remake-plan.json`。本輪不改正式鍵盤語意，不能稱逐鍵完全相同。
英文遊戲已返回 0 並產生完整 trace，但核對腳本讀錯 `town.party` 的層級；改核對後
沿用成功遊戲輸出，沒有重跑英文。雙語唯一差異已定位到 `battle.encounter_text`。
