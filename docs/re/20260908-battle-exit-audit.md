# 戰鬥敗北出口與舊掉落結論稽核

日期：2026-09-08。文件證據審查，沒有執行新的反組譯或原版實驗。

## 原始定位與證據等級

既有研究輸入 `KOLTOWN-unpacked.EXE`，SHA-256：
`01f6f9a95c4adf8e9da59fa83bae57aa282e5576767b41bfc2f23302aeb9d1d2`。
下列地址沿用既有 IDA Pro 9.4 線性位址空間，不是檔案偏移。

- `sub_1E3A8:0x21765`／`byte_3AC7D`：舊研究在
  `docs/re/RESEARCH-LOG.md` 的「逃走之後不會掉東西：機率恆為零」段，
  以一個直接讀取交叉參照、零個直接寫入交叉參照與未初始化資料區位置，
  將「機率恆為零」標成已證實。
- **本輪審查：該恆零結論證據不足，現行工作只能視為待驗假說。**
  直接交叉參照沒有寫入，不足以排除暫存器／指標間接寫入或整區初始化。
  載入映像範圍之外也不能單獨證明所有可達時點的值不變。
  此訂正保留原段落及定位，不宣稱已證實存在非零寫入或原版必然掉落。

## 玩家路徑的實際缺口

現行 `cmd/kol/battle_inventory.go` 的 `writeBattleParty` 排除敗北，
`cmd/kol/main.go` 的 `battleStep` 卻清除戰鬥狀態返回世界，並保留
「打輸之後原版怎麼處置還沒解」註解。這是目前程式的靜態事實；
不能由勝利／撤退保存測試推成敗北已完成。

下一個窄任務需以既有 `.i64` 追查共同出口與角色傷勢寫回、
`byte_3AC7D` 的取址及間接寫入，並由 dosgolem 固定 seed 重生一條敗北出口收據。
先分開一般戰鬥與競技場，不把其中一條規則套到另一條。
證據足夠後回填 DRAFT／READY 契約，再修正式路徑及同狀態驗證；
不得為了填滿缺口而直接採用勝利的角色回寫規則。
## 同日後續補證：共同傷勢出口已關閉

以既有 IDA 9.4 資料庫暫存副本追查，`sub_1E3A8` 終於 `0x218FA`，
`0x2186E..0x218E8` 是各結果共用的傷勢回寫；只處理陣營零的隊員，
將戰中與角色原傷勢的差以 16-bit 無號除二，再把 AL 加回角色 `+0x1B`。
dosgolem 4608 組直接比較通過，正式計算及五條保存鏈亦通過。
這已足以推翻重製版「全額保存戰中傷勢」及「敗北完全不回寫」的實作，
已依 SPEC-027 READY 修正；並未關閉上方掉落恆零假說。
完整收據見 [共同出口修正](../verification/battle-exit-wounds-20260908.md)。
