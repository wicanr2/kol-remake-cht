## 左上框

**已證實**：立即值 0x101 的四個錨點只有 `sub_22EFC` 的兩處是裝備文字讀取；
另外兩處分別是矩形座標及壓縮字典常數，不能把常數相同視為同一用途。

`sub_22EFC:0x22F19` 畫左上框。隊員分支先在文字欄 3、掃描列 7 畫角色名稱。
`word_303FC` 為非零時才畫 0x101 模板與裝備；零分支改呼叫 `sub_1C53D`，資料指標
取 DS 相對 `0x3254 + index*0x2F8`。該分支為預先準備角色立繪屬**強推論**，
仍需繪製來源／動態畫面核對，不把預先存在的名稱或函式名稱當成證明。

**已證實**：隊員六列裝備的位移表位於 IDA linear `0x2EA50`，等同 DS 相對 `0x0B80`，
原始 bytes `300000011001200160019001`，即手持、頭、軀幹、腿、盾、腰帶。
名稱使用文字欄 5、掃描列 24 起，每列加 6。敵方分支從裝備基底 +0x20 起讀五列，
不可直接把隊員的六列映射套在敵人上。

模式寫入端已定位：`0x1F155` 設零，`0x118BE` 與 `0x2474F` 以 XOR 1 反轉。
**未知**：兩個切換端的玩家按鍵／圖示，以及設零的精確時機，尚待呼叫端上下文查核。
第一次匯出用 `xref.iscode` 篩選而漏掉資料參照；改為檢查來源地址是否為指令後，
才取得這些讀寫端。空清單是工具篩選問題，不能當成沒有寫入者的證據。

## 左下框與疲勞直條

**已證實**：`sub_2324F` 讀取參戰者 DS 相對 `0x1C50+2*index`（體力）及
`0x322E+2*index`（疲勞）。直條不是生命值。以 `S` 表示體力、`F` 表示疲勞，
原始有號整數運算分步為：

```
A = (2*S - F) / 2
B = (A*100) / S
Y = clamp(84 + ((100-B)*72)/100, 84, 155)
```

每個除法均向零截斷，不能先化簡成單一比例。矩形一為 `(132,84)..(138,Y)`，
非單色分支色碼 12；矩形二為 `(132,Y)..(138,156)`、色碼 1。
單色分支另選色碼 15，本輪動態測試不涵蓋該模式；S=0 不在本次有效輸入範圍。

**已證實**：隊員以 `0x47 + 性別 byte` 呼叫 `sub_27E20`，敵方固定傳 `0x49`。
**未知**：該 helper 如何合成人形、部位傷勢、素材來源與遮罩；不能只拿參數當 PNG 索引。
`sub_2324F` 的非零參數還會畫命令相關圖示，本輪以參數零排除，未宣稱完整左下框已驗收。
