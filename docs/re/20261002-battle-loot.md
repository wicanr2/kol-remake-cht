# 戰後搜刮控制與邊界（RE-182）

本輪補足[RE-181](20261002-battle-settlement.md)的搜刮草案。原版正常61回合續跑的
351個輸入、122個邊界、1491個亂數入口、訊息及八個戰後狀態與RE-181完全相同。
新增原始位址唯讀觀察確認：`0x211AD`暫存為2，原指令清零後，`0x21607`、
`0x2175B`、`0x21765`均為0；不能用出口前或返回世界後的值代替分支當下的值。

輸入為`KOLTOWN-unpacked.EXE`，SHA-256
`01f6f9a95c4adf8e9da59fa83bae57aa282e5576767b41bfc2f23302aeb9d1d2`；
IDA Pro9.4／IDA linear，正式資料庫SHA-256
`5c32c977bd420c3a51e5c068ece78f830c4f252445cf138623fbaba64fe551c8`。
執行工具為dosgolem `968ca774705853276ae55c8d1163c369481ac71f`，記錄欄位採DGROUP
相對位移。原名、位址、bytes、operand、xref與分級索引同列，不改正式資料庫。

## 已證實的控制與保護

- `0x211B9`將共用暫存`word_3AC5A`清零；怪物倒地計數等於總數時，勝利分支
  `0x21249`加一，`0x2175B`非零即跳過搜刮。一般與升階出口共用此閘門，不能
  只因競技場就免除敗北搜刮。兩側同倒時，出口仍先查怪物計數；此處不能只
  依重製回合的單一Verdict猜測原版出口標記。
- `sub_22866`只看原版頭`+0x11`或胸`+0x13`是否為`0xFF`；重製的失效部位
  使用0。案例使用原版真正失效標記，沒有把原始0當0xFF。
- `sub_2886C`由`word_34968`控制，非零才逐byte比較完整16-byte任務記錄。
  現行24個任務的完整記錄及既有258組比對證據見[SPEC-014](../spec/014-quest-completion.md)。
- 門檻、15槽＋錢包、`+0x170`無條件跳過、空格仍擲、嚴格小於與整槽清零
  延續RE-181證據。物品清除保留原位，後方物品不往前搬。

修正另產收據，不把舊收據改寫成新版本已通過。
