# 文字與字型

原版的文字分成三套完全不同的東西：**字模**（畫在畫面上的點陣圖）、**UI 文字庫**
（KOLDATA／BOOKDATA／ENDTXT 的 ASCII 記錄）與**城鎮文字**（TOWNn.0 裡 5-bit 打包的
九千多行對話）。三套的儲存方式、索引方式與排版規則都不一樣，混在一起想會很亂。

## 字模：兩份 8 像素寬的表

`BOOKDATA.0` 與 `KOLDATA.0` 的第一個 payload 是**同一份** 1,303-byte 區塊
（SHA-256 `819e4f82…d318`）：

- 前 744 bytes：93 個 **8×8** 字模
- `0x2e8` 起：93 個 **8×6** 字模

都從 ASCII 32 起算，涵蓋 32–124。城鎮畫面用 8×8 大字型，書頁內文用 8×6 小字型
（RE-042）。抽取器是 `tools/extract_fonts.py`，輸出到
`assets/original-derived-png/fonts/`。

**原版的繪字規則**：逐字模格清成白底再畫墨點，**但空白字元不清底**——所以空白會讓
底下的東西透出來。這條規則是書本文字對拍能收斂到零像素差的關鍵（RE-043）。

## UI 文字庫：三個 bank，以記錄號索引

| bank | payload | 筆數 | 內容 |
|---|---|---:|---|
| KOLDATA | 1 | 395 | 城鎮與戰鬥的 UI 訊息 |
| BOOKDATA | 1 | 73 | 書本 UI 與工作人員名單 |
| ENDTXT | 0 | 18 | 結局敘事 |

記錄以 `\r`（0x0D）分隔，`sub_1A8FD(記錄號, 文字庫基址)` 逐字掃出來畫。
抽取器 `tools/extract_ui_text.py` → `assets/original-derived-data/ui-text.json`。

### 記錄裡的四種記號（RE-086）

| 記號 | 意思 |
|---|---|
| `@` (0x40) | 換行：X 回到左緣，Y 加 `2 × 字高 + 6` |
| `]` (0x5D) | 換成一個空白（常在句尾，因為下一段會直接接上來） |
| `~Vxx`／`~Hxx`／`~Cxx` | 掃描列／欄／置中，三個字元的十六進位參數 |
| `\|X` | 代換碼，執行期換成名字、代名詞或武器名 |

十一個代換碼由 `sub_265F3` 的分派表處理：`|A`／`|B` 是所有格，`|C`／`|D` 是受格，
`|E` 是武器名，`|F`／`|G` 是名字，`|H`／`|I`／`|S` 是物品名，`|N` 是數字。
行動者是 `word_37D2A`、目標是 `word_3237E`。**代換之前會先補一個空白**
（`sub_265F3:0x265FC`），少了它 `kicks|B leg` 會變成 `kickshis leg`。

### 訊息不是句子，是碎片

戰鬥訊息由多筆記錄串接而成，例如一次攻擊是「動作動詞」＋「`|B|E at|F`」＋
「命中或落空的結果」三到五筆（RE-088）。**這決定了中文化的做法**：一筆記錄對一筆
譯文，各自譯成「接得上去的片段」，而不是整句模板——否則譯文與原版記錄失去一一對應，
之後對不了帳。譯文在 `docs/i18n/ui-zh-Hant.json`，檢查器是
`tools/verify_ui_translation.py`。

## 城鎮文字：5-bit 打包

`TOWNn.0` 裡從位移 128 起，每 **16 byte** 一格：第 0 byte 是字數，其後 15 byte 塞
24 個 **5-bit** 字元。小寫是預設，大寫靠一個記號切換（RE-062）。

解碼器 `sub_1B94F` 讀出來之後，RE-062 當初用統計猜的七個符號全部命中，字元表因此由
強推論升級為**已證實**（RE-064）。同一輪也解開兩個怪現象：引號會吃掉一個空白、
`[1B][1B]` 等於 `!"`。

一則訊息固定 **4 格 ＝ 64 byte**（`sub_14234` 的迴圈上限 `40h`、步進 `10h`）。
七座城 101 棟建築共 9,515 行，抽出來放 `assets/original-derived-data/town-text.json`。

**畫面上的兩條排版規則**：句號後補兩個空白且下一個字母大寫、逗號後補一個空白。
套上之後與原版逐字相同。

## 中文模式

繁體中文字形放不進 8×6 的格子，所以採**雙模式**：

- **英文模式** 320×200，走原版字模，供嚴格對拍
- **中文模式** 960×600，16×18 的中文字模格（倍率三：原版最小行距 6 × 3 ＝ 18，
  剛好等於字模格高；見 SPEC-030）

字模由 `tools/build_cjk_font.py` 從 Noto Sans CJK TC（SIL OFL 1.1）烘成點陣表，
執行期只讀 PNG，不在執行期做字型排版。目前 2,434 字。

兩個模式的**欄數相同**（320/8 ＝ 640/16 ＝ 40），所以 `~Hxx` 可以直接沿用；
`~Vxx` 是掃描列，200 對 400，要由 code 換算。

版面驗證有兩層：`tools/verify_text_fit.py` 用實際字寬檢查每個字串畫得進所屬的文字
安全矩形（目前 6,685 項），`tools/verify_ui_translation.py` 檢查譯文沒有把控制碼弄丟。
